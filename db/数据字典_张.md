# 智选志愿 · 数据库数据字典（河南试点 v1）

> 归属：角色 ③ 数据工程 + 数据库设计（张）｜ 对齐《开发产品书_智选志愿》第 7 章数据模型
> 对应 DDL：`db/schema.sql` ｜ 生成日期：2026-10-11
> 目标库：PostgreSQL 16（pgvector 选装）

本字典是**字段口径的唯一权威**。后端 models、算法向量化、前端 types 都以此为准；
任何字段增删改须走产品书 9.2 的「③④② 三方确认」。

---

## 0. 使用与约定

| 项 | 约定 |
|---|---|
| 数据库 | `zhixuan`，schema `public` |
| 主键 | `id BIGSERIAL`（自增） |
| 时间 | 统一 `TIMESTAMPTZ`，默认 `now()`；`created_at / updated_at` 由触发器维护 |
| 省份 | 统一 `province = '河南'`（试点），字段保留以便后续扩省 |
| 年份 | `year SMALLINT`，CHECK 2000–2100 |
| 事实表铁律 | 每张事实表 **必有** `source_id NOT NULL`（外键→`source`）**且** `year`，保证可溯源 |
| 枚举 | 一律用 `CHECK` 约束，禁止魔法值 |
| 密码 | 只存 `password_hash`（bcrypt），禁止明文 |
| 向量 | `embedding vector(512)`（bge-small-zh-v1.5，入库前 L2 归一化）；pgvector 未装时该列不创建 |

### 分层

```
L0 来源与暂存   source, stg_import
L1 途径与政策   pathway, pathway_eligibility, pathway_region
L2 院校与专业   school, major
L3 分数事实     school_major_score, pathway_score, score_segment, batch_score_line
L4 章程画像     enrollment_rule, school_profile, discipline_eval, school_life
L5 知识库       knowledge_doc, knowledge_chunk
L6 用户与运维   app_user, user_profile, user_favorite, user_plan,
                qa_log, review_task, admin_user, admin_audit_log
```

## 2. L0 · 来源与暂存

### 2.1 `source` —— 一切事实数据的锚点

| 字段 | 类型 | 约束 | 含义 |
|---|---|---|---|
| id | BIGSERIAL | PK | 主键 |
| source_name | TEXT | NOT NULL | 来源名称，如"河南省阳光高考信息平台" |
| source_url | TEXT | NOT NULL | 来源 URL |
| year | SMALLINT | NOT NULL, 2000–2100 | 数据年份 |
| source_type | TEXT | NOT NULL, ∈{官方,公开网络,投稿} | 来源类型 |
| reliability | TEXT | NOT NULL, ∈{high,medium,low} | 可靠性 |
| fetched_at | TIMESTAMPTZ | NOT NULL | 最近抓取时间（重载时更新） |
| created_at | TIMESTAMPTZ | NOT NULL | 登记时间 |

**唯一键**：`(source_name, source_url, year)`
**登记规则**：入库前先登记来源，再以 `source_id` 引用。缺来源三要素（名称/URL/年份）的行在清洗阶段即被拒收。

| source_name | TEXT | NOT NULL | 来源名称 |
| source_url | TEXT | NOT NULL | 来源 URL |
| year | SMALLINT | | 年份 |
| doc_type | TEXT | | 数据类型标识（见 §7） |
| raw | JSONB | NOT NULL | 一行原始记录（完整保留） |
| row_no | INTEGER | | 行号 |
| status | TEXT | NOT NULL, ∈{new,validated,loaded,rejected} | 状态 |
| reject_reason | TEXT | | 拒收原因 |

> 说明：`stg_import` 是**追加式导入日志**（每个 `batch_no` 追加），用于回溯与回放；事实表本身幂等，重跑不产生重复。

## 5. L3 · 分数事实（冲稳保的地基）

### 5.1 `score_segment` —— 一分一段表

| 字段 | 类型 | 约束 | 含义 |
|---|---|---|---|
| id | BIGSERIAL | PK | 主键 |
| province | TEXT | NOT NULL 默认河南 | 省份 |
| year | SMALLINT | NOT NULL | 年份 |
| subject_type | TEXT | NOT NULL, 枚举 | 科类 |
| score | INTEGER | NOT NULL, 0–750 | 分数（区间段取下界） |
| score_end | INTEGER | | 区间上界（仅最高分段，如 710–750） |
| same_score_count | INTEGER | | 本段人数 |
| cumulative_rank | INTEGER | NOT NULL | 累计人数（该分及以上） |
| source_id | BIGINT | NOT NULL → source | 来源 |

**唯一键**：`(province, year, subject_type, score)` ｜ 索引：`idx_seg_score`、`idx_seg_rank`
> **位次差法全靠它**，故最先采、必须最准；且同一科类同年份"分数降序 ⇒ 位次升序"须单调（校验项）。

### 5.2 `school_major_score` —— 院校专业组录取分 / 投档线

| 字段 | 类型 | 约束 | 含义 |
|---|---|---|---|
| id | BIGSERIAL | PK | 主键 |
| school_id | BIGINT | NOT NULL → school | 院校 |
| major_id | BIGINT | → major | 专业（**院校专业组投档时为空**） |
| province | TEXT | NOT NULL 默认河南 | 省份 |
| year | SMALLINT | NOT NULL | 年份 |
| batch | TEXT | NOT NULL | 批次（见 §1 统一口径） |
| subject_type | TEXT | NOT NULL, 枚举 | 科类 |
| group_code | TEXT | | **院校专业组代码（新高考 2025+ 关键字段）** |
| group_name | TEXT | | 专业组名称（聚合后追加"（N个专业）"） |
| min_score | NUMERIC(6,1) | | 最低分（投档线） |
| min_rank | INTEGER | | 最低位次 |
| avg_score | NUMERIC(6,1) | | 平均分 |
| plan_count | INTEGER | | 招生计划数 |
| pathway_id | BIGINT | → pathway | 专项计划录取时关联 |
| source_id | BIGINT | NOT NULL → source | 来源 |

**唯一键**：`UNIQUE NULLS NOT DISTINCT (school_id, major_id, province, year, batch, subject_type, group_code)`
**索引**：`idx_sms_core`、`idx_sms_school`、`idx_sms_rank`、`idx_sms_path`
> **投档单位 = 院校专业组**。入库前，`data/loaders/pg.py::_aggregate_school_major_score` 把专业级明细聚合到组级：
> `min_score = 组内各专业最低分的最小值`、`min_rank = 最优`、`plan_count = 求和`、`avg_score = 均值`。
> 这样既符合 schema 语义，又避免 `major_id=NULL` 时多行互相覆盖（幂等）。

### 5.3 `pathway_score` —— 专项/特殊路径录取分（D-4，P0）

同一张表记录「哪条途径 × 哪所学校 × 哪一年 × 哪个科类 × 哪个院校专业组」的录取分。

| 字段 | 类型 | 约束 | 含义 |
|---|---|---|---|
| id | BIGSERIAL | PK | |
| pathway_id | BIGINT | NOT NULL → pathway | 途径（国家专项计划 / 地方专项计划 / 高校专项计划） |
| school_id | BIGINT | NOT NULL → school | 院校 |
| major_id | BIGINT | → major | 专业（专项按组投档，通常为空） |
| province | TEXT | NOT NULL 默认河南 | 省份 |
| year | SMALLINT | NOT NULL | 年份 |
| batch | TEXT | | 批次（2025 起专项并入 `普通本科批`） |
| subject_type | TEXT | 枚举，可空 | 历史类 / 物理类 / 文科 / 理科 / 综合 |
| group_code | TEXT | | **院校专业组代码**（如 `301`），2025 新高考关键 |
| group_name | TEXT | | 组名原文，如「本科批：第301组(国家专项计划)」 |
| min_score | NUMERIC(6,1) | 0–750 | 最低录取分 |
| max_score | NUMERIC(6,1) | 0–750 | 最高录取分（官方新闻口径才有） |
| min_rank | INTEGER | | 最低分对应位次 |
| admitted_num | INTEGER | | 录取人数（来源公布时） |
| source_id | BIGINT | NOT NULL → source | 来源 |

**唯一键**：`(pathway_id, school_id, province, year, subject_type, group_code)`（`NULLS NOT DISTINCT`，
保证 `group_code` 为空的官方新闻口径行也能幂等 upsert）
｜ 索引：`idx_pathway_score_lookup`、`idx_pathway_score_school`

> **为什么要单独建表而不并入 `school_major_score`**：专项计划只面向**资格考生**（县名单 + 户籍/学籍），
> 其录取分通常比普通批低 10–60 分；混入普通批次会把冲稳保梯度算歪，且无法反向回答
> 「我符合国家专项资格，能上哪些学校」。故专项分按途径维度独立落表。
>
> **采集来源**（`data/collectors/c_pathway_score.py`）：
> 1. 高校招生网《XXXX 年在豫招生各批次及各专业组录取分数一览表》——静态 HTML 表格，
>    专项组明确标注（如「本科批：第301组 ( 国家专项计划 )」），含最低分 + 位次；
> 2. 政府门户 / 官方新闻公布的专项录取分——纯文本，形如「国家专项历史类最低录取分598，最高录取分619」；
> 3. `data/seeds/pathway_scores.json` —— 在线源全空时的兜底（人工核验官方数值）。
>
> **扩展方式**：新增院校只需在 `c_pathway_score.py::REGISTRY` 追加一行（school_name / school_code / year / url / kind）。

### 6.3 `discipline_eval` / `school_life`（P1/P2，**已接入采集**）

## 9. 采集 → 清洗 → 入库 全链路

```
公开站点 ──采集(c_collectors)──▶ RawRecord(data + 来源三要素)
                                     │
                          清洗校验(cleaners/normalize.py)
                          ├─ 来源三要素缺失 → 拒收 → reject_report.json
                          ├─ 业务校验(枚举/范围) → 拒收
                          └─ 按业务主键去重 → 合格行
                                     │
                     输出 output/<doc_type>.json|.csv
                                     │
                     入库(loaders/pg.py, --load-db)
                     ├─ ensure_source  → 登记来源拿 source_id
                     ├─ stage          → 写 stg_import（原始 JSON）
                     └─ upsert         → 正式表（幂等）
```

**每日验收 SQL**：

```sql
-- 一分一段按年/科类计数
SELECT year, subject_type, count(*) FROM score_segment GROUP BY 1,2 ORDER BY 1,2;
-- 铁律：来源缺失必须为 0
SELECT count(*) FROM score_segment WHERE source_id IS NULL;   -- 期望 0
-- 各来源覆盖率
SELECT s.source_name, count(*) FROM school_major_score m
JOIN source s ON s.id = m.source_id GROUP BY 1 ORDER BY 2 DESC;
-- D-4 专项录取分：按途径 × 院校
SELECT p.name, sc.name, ps.year, ps.subject_type, ps.group_code, ps.min_score
FROM pathway_score ps
JOIN pathway p ON p.id = ps.pathway_id
JOIN school  sc ON sc.id = ps.school_id
ORDER BY p.name, sc.name, ps.group_code NULLS LAST;
```

## 10. 已知限制与待办

1. **pgvector 选装**：未安装时 `knowledge_chunk.embedding` 不创建，向量检索功能待环境就绪后启用。
2. **`school_major_score` 专业级明细**：入库聚合为"院校专业组"级；如需保留专业级，须经三方确认后新增 `major_name` 列并调整唯一键。
3. **`stg_import` 追加式**：每个 `batch_no` 追加写入（审计日志），事实表幂等。
4. **P2 途径**：采不到数据的途径标 `data_status='schema_only'`，界面显示"规划中"。
5. **合规**：一分一段/院校库来自中国教育在线·掌上高考（`公开网络`），已在 `source_type` 如实标注；建议补官方交叉源。
6. **D-9 学科评估轮次**：首批为第四轮（2017 公开汇总）。第五轮结果官方尚未全部公开，发布后按同结构增量（唯一键含 `round`，可直接并存）。
7. **D-11 生活信息覆盖偏低**：源（院校简介）文本仅约 170 字，缺少宿舍/食堂细节，故仅抽到 7 条；如需扩大覆盖，需接入各校《新生入学须知》等更细文本。
8. **省份**：当前仅河南；江西为二期（采集器已按 `province` 参数化）。
9. **与 Trae/OpenSpec 侧的差异**：科类字段口径（`subject_type` vs `first_subject`）、江西范围、问答接口形态，见 `与Trae侧冲突排查_张.md`。
