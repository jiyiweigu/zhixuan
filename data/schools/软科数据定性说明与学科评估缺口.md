# 软科数据定性说明 & 学科评估缺口（D2 交付）

> 编制：徐（③ 数据工程）｜ 2026-10-13 ｜ 脚本：`data/scripts/build_school_type_supplement.py`
> 目的：纠正任务清单 D2 的原始假设，并给出软科数据**真正能用**的地方。

---

## 一、纠正：软科数据**不是**学科评估

原清单把 D2 写成「软科 JSON → `discipline_eval` 表」。**这个前提是错的**，实测依据：

| | `DisciplineEval` 模型要什么 | 软科 JSON 给什么 |
|---|---|---|
| 粒度 | **学科**（`discipline_name` 如「计算机科学与技术」） | **院校**（`name` 如「清华大学」） |
| 结果字段 | `grade` 评估等级（A+ / A / B） | `ranking` / `rankOverall` / `score` |
| 轮次 | `round`（如「第四轮」） | 无（年度排名） |
| 发布方 | 教育部**学位与研究生教育发展中心** | 上海软科（第三方商业机构） |

⇒ **软科院校排名不能充当学科评估**，两者既不同源也不同粒度。

### 学科评估的官方源实测

| 源 | 实测结果 |
|---|---|
| `https://www.cdgdc.edu.cn/` | **HTTP 412**（瑞数 WAF） |
| `https://www.cdgdc.edu.cn/xwyyjsjyxx/xkpgjg/` | **HTTP 412** |

与本项目已知被拦的 `haeea.cn` / `heao.com.cn` / `gaokao.chsi.com.cn` **同一类**。
⇒ 只能「人工下载第 N 轮学科评估结果附件 → 脚本解析」，非纯脚本可完成。

`source` 表中已有占位登记：`SRC-MOE-DEGREE`（教育部学位与研究生教育发展中心（学科评估），year=2022）。

**③ 结论**：本轮**不产出** `discipline_eval`，也**不臆造**。需队长决定是否投入人工采集。

## 三、⚠️ 使用边界（务必随文递交 ②/队长）

1. **非官方口径**。软科是第三方商业机构排名，其 `univCategory` **不得**表述为官方分类。
2. `SRC-SHANGHAIRANKING` 在 `source` 表登记的用途是「**参考位次 / 层次校验辅助**」。
   把它用于 `school.type` **超出了登记用途** ⇒ 需队长/② 裁定，或另行登记用途。
   故本产物**命名为 `supplement`（候选补充）**，由 ② 决定是否合入。
3. **建议合入方式**：仅在 `school.type` 为空时填充，并在前端标注来源；官方口径仍以 D5 逐校官网采集为准。
4. 覆盖 78.6%，**剩余 292 所无法由任何软科榜单覆盖**（军校等），须 D5 采集。
