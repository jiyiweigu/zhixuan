## 0. 一句话结论

**这批数据不是"外部数据"，而是"同一批官方数据的另一条采集路径"。** 实测证实：江西 2024 一分一段与我方已有数据 **1148/1148 条数值完全一致**，但**来源不同、且带可访问 URL** —— 因此它的最大价值可能不在"新增行数"，而在**给已有数据补来源、做交叉验证**。

## 4. 五条通用转换规则

### R1 · 业务键 → 内部 id（**最关键，且这条路是通的**）

张用 `school_code`/`major_code`/`school_name`，我方用自增 `school_id`/`major_id`。

| 项 | 实测 | 结论 |
|---|---|---|
| 院校码体系 | 张 `code` = **国标码**（10403 南昌大学）｜我方 `school.code` = **国标码** | ⚠️ **码本身同体系，但我方同 code 多行**（1,366 code ↔ 1,453 行）⇒ **必须配 name 消歧**，见 §3.1 补注 |
| 专业码体系 | 张 `major.code` = 专业国标代码｜我方 `major.code` 同 | ✅ 可直接 join |

流程：`code` 精确匹配 → 未命中走 `AliasIndex`（我方已有 82 条别名 + 465 条 `name_repair`）→ 仍未命中**列出待人工**。
> ⛔ **禁止用编辑距离自动修名**（已实证「榆林学院」会唯一命中「桂林学院」——不同实体）。

### R2 · 枚举收敛到 v1.3

| 字段 | 张取值 | 我方 v1.3 | 映射 |
|---|---|---|---|
| `data_status` | `available` / `schema_only` | `available`/`partial`/`schema_only`/`unavailable` | **子集，直接可用**；但**一省数据不宜标 `available`**，应按覆盖度降级为 `partial` |
| `source_type` | `官方` / `公开网络` / `投稿` | `官方`/`高校官网`/`权威媒体`/`其他` | `官方`→`官方`；`公开网络`→**按站点判**（如掌上高考 eol.cn 应归 `权威媒体`）；`投稿`→`其他`。**映射表需队长确认** |
| `source.reliability` | `high/medium/low` | 无此列 | ➖ 丢弃 |

> ⚠️ 契约 **禁用** `verified`/`pending`/`mock`。

### R3 · 类型收敛

| 张 | 我方 | 处理 |
|---|---|---|
| `BIGSERIAL` (64 位) | `Integer`/`Serial` | 导入时由我方生成 id，**不搬张的 id** |
| `TIMESTAMPTZ` | `timestamp without time zone` | 去时区（统一按本地时间） |
| `JSONB` | `JSON` | 直接写入（PG 自动降级） |
| `numeric(6,x)` 分数 | `integer` | **取整前需确认**：分数若含小数（如 `581.5`）会**丢精度** ⇒ 需队长确认口径 |

### R4 · `pathway_name` → `pathway_id`

张的 `pathway_eligibility`/`pathway_region`/`pathway_score` 用 `pathway_name` 引用，我方 `pathway.id` 是 **VARCHAR 编码**。
→ 必须建 `pathway_name → pathway.id` 对照（我方 26 类途径字典 `data/dictionaries/pathways-26.json`），**未命中的显式报错**，不猜。

### R5 · 三要素 → `source` 表（**必须先于其他表**）

张的每条记录内嵌 `source_name`/`source_url`/`year` —— 这是**优点**（三要素齐）。
但导入顺序必须是：**先灌 `source`（去重登记）→ 得 `source_id` → 再灌事实表**，否则外键悬空（`source_id` 在 20+ 张表里是 **NOT NULL**）。
> 复用我方 `data/mappings/source-id-map.json` 机制，**同一来源不要登记出两个 `source` 行**。
