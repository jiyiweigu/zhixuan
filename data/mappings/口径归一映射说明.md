## 一、为什么需要：四处口径分裂

这些分裂不是笔误，而是**采集产物忠于原始数据源**（各省官方各写各的）与
**契约要求跨省归一**之间的必然产物。不解决，灌数后表现为「查不到」或
「同一批次被当成两个批次」。

| # | 口径 | ③ 采集侧（原始） | 契约 / 模型侧（目标） | 后果 |
|---|---|---|---|---|
| 1 | **省份码** | 6 位码 `410000`；省名有「河南」「河南省」两种写法 | 契约 8.3/8.6/8.7 用 **2 位**码 `41`/`36` | 接口按 `41` 查，库里是 `410000` → 空结果 |
| 2 | **批次码** | 同一语义 **21 种**中文写法 | `batch_code` 机器键、唯一键；「归一后不得再区分」 | 河南「本科一批」与「本科第一批」成了两个批次 |
| 3 | **科类** | 老高考「理科/文科」+ 新高考「物理类/历史类」混存 | 模型注释「物理类 / 历史类」 | 跨年趋势查不出；位次口径混淆 |
| 4 | **考试类型** | 河南「普通类」/ 江西「历史、物理科目组」 | 契约 8.3 示例 `exam_type="普通"` | 唯一键 `(省,年,批次,exam_type)` 跨省对不上 |

## 二、四张映射表速览

### 2.1 `province-code-map.{json,csv}` — 省份三向映射（G6）

- **31 个高考招生省级行政区**全登记（依据 GB/T 2260）。
- 当前数据覆盖 **2 个省**：河南 `41`/`410000`、江西 `36`/`360000`。
- 内置 `by_name` / `by_code2` / `by_code6` 三个索引，可直接双向转换。
- **验证**：数据里出现的每一种省名写法（含 `province_raw` 的「河南省」）
  都能命中 → `unmapped_names: []`。

**推荐口径**

| 场景 | 建议取值 |
|---|---|
| 契约接口入参 / 规则类表落库 | **2 位码**（`41`） |
| 事实表（`score_segment` / `school_major_score`）的 `province` 字符串列 | **中文简称**（`河南`） |
| 6 位码 | 仅作 ③ 产物的历史口径保留，落库前转 2 位 |

> ⚠️ 数据里「河南省」这一写法出现在 `pathway-regions.province_raw`（归一前原值留痕）。
> 事实表入库前须经 `by_name` 归一为「河南」。此处的 144 条归一已在 D7 完成。

### 2.2 `batch-code-map.{json,csv}` — 批次码归一（G7）

**21 个中文原值 → 8 个 `batch_code`**：

| batch_code | 统一展示名 | 覆盖的中文原值 | 行数 |
|---|---|---|---|
| `undergraduate_regular` | 普通本科批 | 本科 / 本科批 / 本科批次 / 普通本科批 | 127,370 |
| `undergraduate_first` | 本科一批 | 本科一批 / 本科第一批 / **本一** | 85,968 |
| `undergraduate_second` | 本科二批 | 本科二批 / 本科第二批 / **本二** | 115,933 |
| `undergraduate_early` | 普通本科提前批 | 本科提前批 / 提前本科 / 普通本科提前批 | 2,675 |
| `undergraduate_special` | 特殊类型选拔本科 | 高校特殊选拔本科 | 1,048 |
| `undergraduate_art_sport` | 艺术类/体育类本科批 | 艺术类/体育类本科批次 | 1 |
| `vocational_regular` | 高职（专科）批 | 专科批 / 高职专科批 / 高职(专科) / 高职（专科）批 / 高职（专科）批次 / 普通高职（专科）批 | 149,149 |
| `vocational_early` | 高职（专科）提前批 | 提前高职(专科) | 642 |

**命名规则**：`{level}_{batch}`，`level ∈ {undergraduate, vocational}`。

**★ 决策：采用跨省语义码，不采用省前缀（`HE-UG`）**

- 契约 **504-505 行**是强制表述：「各省叫法差异（河南 `普通本科批`、江西 `本科批次`）
  经 `batch_code` 归一后**不得再区分**」。
- 而契约**第 38 行**的示例 `HE-UG` **自带省前缀**，同一批次会产生 `HE-UG` / `JX-UG` 两个码，
  正好违反 504-505 行。
- 二者**自相矛盾**（已在《契约裁决请求》N7 记录）。③ 采用满足强制条款的语义码；
  若队长最终选省前缀方案，映射表已内置 `meta.legacy_contract_example` 给出 `HE-UG`
  → `undergraduate_regular` 的对应关系，其余批次**不臆造**省前缀码。
- 交叉校验：8 个码与 `province-exam-rule.json` 已登记的 `batch_code` **完全一致**。

**★ 一个必须同步解决的阻塞（B-5）**

批次归一做得再干净，**目前也存不进 `score_segment` 表**——
模型 `ScoreSegment` **没有 `batch` 列**，且索引是
`ix_score_segment_lookup = (province, year, subject_type, score)`，**不含 batch**。

而一分一段数据**每行都带 batch**，且老高考一分一段本就是**一条曲线被批次线切成几段**
（同一省同年同科类，「本科一批」「本科二批」「专科批」是**各自独立**的分数段）。
若不加 `batch` 列：不同批次的同名分数会互相覆盖，位次反查直接出错。

→ 这是 B-5 的**数据侧证据**，请 ② 优先加列并把 `batch` 纳入唯一索引 / 索引。

### 2.3 `subject-type-map.{json,csv}` — 科类归一

| 原值 | 归一 | confidence | 行数 |
|---|---|---|---|
| 物理类 / 历史类 | 原样 | high | 109,087 / 52,174 |
| **理科** | 物理类 | **medium** | 174,031 |
| **文科** | 历史类 | **medium** | 95,248 |
| 艺术文 / 艺术(不分科目类) | 艺术类 | high | 4 / 647 |
| **科** / **文** | —（脏值，不归一） | invalid | 6 / 3 |

**★ `medium` 的含义：可归并，但不是等价替换。**
老高考「理科」= 理化生固定组合，新高考「物理类」= 首选物理 + 2 门任选，
考生结构不同 ⇒ **位次不可直接换算、投档规则不可复用**。
映射表内 `equivalent` 字段显式标了 `false`，`note` 写明了限制。

→ 结论：**跨年趋势对比可用；录取概率预测必须按「同年同科类」取数，不得跨口径混用。**

**脏值归属**：2023 河南招生计划出现「科」6 条、「文」3 条，疑为「理科 / 文科」被截断。
按铁律**不猜**，标 `invalid` 待重采（合计 9 行，影响面极小）。

### 2.4 `exam-type-map.{json,csv}` — 考试类型（新发现 N11）

契约 8.7 只说了「数据源列名 `category_group` 对应契约字段 `exam_type`，导入时**必须改名**」，
**没给取值归一规则**。

| 原值（`category_group`） | 归一 | confidence |
|---|---|---|
| 普通类（河南） | 普通 | high |
| 历史、物理科目组（江西） | 普通 | medium |
| 艺术类 / 体育类（江西） | —（**待裁**） | review |

- 河南「普通类」与江西「历史、物理科目组」在契约唯一键 `(省,年,批次,exam_type)`
  下会被当成**两种考试类型**，跨省合并即失效 → 归一到「普通」。
- **江西「艺术类 / 体育类」是 1 条规则同时覆盖两类考生**，而契约 / 模型的枚举是
  **三值**（普通 / 艺术 / 体育），没有「艺术体育」合并值。
  → ③ **不擅自归并**，建议 ② 把该规则**拆为两条**（`exam_type=艺术` / `体育`），
  或由队长放宽枚举。已列入待裁项。

PY=C:/Users/lenovo/.workbuddy/binaries/python/envs/default/Scripts/python.exe

# 生成 4 组映射并做覆盖率 + 交叉校验（未覆盖取值会显式报错，退出码 1）

**可用性实测**（映射确实能跑通，不是纸面表）：

```bash
# 省名归一：把数据里的原始省名映射到 2 位 / 6 位码
$PY -c "
import json
m=json.load(open('data/mappings/province-code-map.json',encoding='utf-8'))['by_name']
for n in ['河南','河南省','江西']: print(n,'->',m[n])
"
# 河南 -> ['41', '410000', '河南省']   河南省 -> ['41', '410000', '河南省']   江西 -> ['36', '360000', '江西省']

# 批次归一：规则表里每个 batch 都能落到统一展示名
$PY -c "
import json
m=json.load(open('data/mappings/batch-code-map.json',encoding='utf-8'))
print(m['display_names'])
"
```

脚本内置**三条硬约束**，任一不满足即报错退出：
1. 数据里出现的任何省份 / 批次 / 科类 / 考试类型原值，**必须**在映射表内登记；
2. 同一 `batch_code` **只能**对应一个统一展示名；
3. 规则表 `province-exam-rule.json` 的 `batch_code` 必须与归一表登记集合**完全一致**。

## 五、给 ② 的集成说明

| 数据列 | 映射动作 | 用哪张表 |
|---|---|---|
| 规则类表的 `province_code` | 6 位 → **2 位** | `province-code-map.by_code6` |
| 事实表的 `province` | 中文名归一（「河南省」→「河南」） | `province-code-map.by_name` |
| 所有表的 `batch` | → `batch_code`；展示取 `display_name` | `batch-code-map.map` |
| `school_major_score.subject_type` / 招生计划 `category` | → 物理类 / 历史类 / 艺术类 | `subject-type-map.map`（**先看 `equivalent`**） |
| `province_exam_rule.category_group` | **改名**为 `exam_type` 并归一 | `exam-type-map.map` + `source_field`/`target_field` |

> 注：`equivalent=false` 的科类（理科 / 文科）在**趋势类接口**可用，
> 在**录取概率类接口**必须拒绝跨口径混用。
