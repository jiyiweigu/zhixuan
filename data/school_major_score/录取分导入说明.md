## 二、口径（红线）

### 2.1 scope：首期只做本科批

依据队长《数据源与数据获取方案》与产品书「首期只做本科批」：

- **专科批全部排除**。原因：`data/schools/schools_merged.json` 是
  **在豫招生的 1367 所本科院校**，**不含专科院校**，专科行的 `school_id` 无法挂上。
- 实测专科命中率：河南 12.9~13.2%、江西 4.2% ⇒ 排除是正确决策，不是丢数据。
- 排除时**逐条记录跳过原因**（`skipped` 统计），不静默丢弃。
- 提供了 `--keep-prep` / `--keep-art` 开关，如需提前批/艺术类可显式打开。

### 2.2 `batch` 必须保留

⚠️ **不得合并批次**。本科一批/本科二批的批次线不同、投档序列不同，
合并会丢失批次线信息（同 `score_segment` 的口径）。

### 2.3 `subject_type` 口径断裂

| 省份 | 老高考（文理科） | 新高考（3+1+2） |
|---|---|---|
| 河南 | ≤ 2024：`文科` / `理科` | ≥ 2025：`物理类` / `历史类` |
| 江西 | ≤ 2023：`文科` / `理科` | ≥ 2024：`物理类` / `历史类` |

必须用 `subject_type` + `exam_system` 双重标记，**不得跨考试制度比较**。

### 2.4 `admit_count` ≠ `plan_count`

- `admit_count`（实际录取数）来自录取表；
- `plan_count`（招生计划数）来自 `enrollment-plan.csv`。

**本表不混填**：`plan_count` 留在计划表，避免口径污染。`admit_count` 作为
辅助字段留存（第 7 章无此列，供 ② 参考）。

### 2.5 `max_score` 不落库

第 7 章 `school_major_score` **无 `max_score` 字段**，且原始数据中 `max_score`
几乎全表为空（见 §4.3），故**不落库**。

| 绍兴文理学院 | **绍兴大学** | 10349 |
| 榆林学院 | **榆林大学** | 11395 |
| 皖南医学院 | **皖南医科大学** | 10368 |
| 滨州医学院 | **山东第二医科大学** | 10438 |
| 防灾科技学院 | **应急管理大学** | 11104 |
| 合肥学院 | 合肥大学 | ✓ 已核 |
| 赣南医学院 | 赣南医科大学 | ✓ 已核 |
| 桂林医学院 | 桂林医科大学 | ✓ 已核 |
| 海南医学院 | 海南医科大学 | ✓ 已核 |
| 佛山科学技术学院 | 佛山大学 | ✓ 已核 |
| 福建工程学院 | 福建理工大学 | ✓ 已核 |
| 赤峰学院 | 赤峰大学 | ✓ 已核 |

> ⚠️ **本脚本不做自动改名推断**（会把「XX学院」误猜成「XX大学」，风险高）。
> 改名映射已**逐条核实后**单独维护于 `data/schools/school_aliases.json`，
> 生成脚本 `data/scripts/build_school_aliases.py`，详见 **§4.6**。

**② 军事院校**：`91xxx` / `92xxx` 代码，不列入教育部普通高校名单，**匹配不上是正确的**。

**③ 独立学院 / 分校区**：如 `北京理工大学珠海学院`、`复旦大学上海医学院`、
`华北电力大学(北京)` vs `(保定)` 等，名称书写差异。

### 4.5 归一化处理（已实施）

仅做**确定无歧义**的归一化：
- 全角括号 → 半角
- 去空格
- 反复剥离尾部括号（`X(原Y)` → `X`）取**核心名**兜底

**不做**改名推断。

### 4.6 ★ 院校改名别名表（已实施，`school_aliases.json`）

**问题**：院校库取自 **2026 河南招生计划**，录取分覆盖 **2022–2025**，期间改名院校无法按名匹配。

**解法**：`data/scripts/build_school_aliases.py` 生成 `data/schools/school_aliases.json`，
数据来源**两条，均不靠推断**：

| 来源 | 条数 | 说明 |
|---|---:|---|
| ① 院校库**自身内联**的 `新名(原旧名)` 标注 | 44 | 正则 `^(.+?)\(原(.+?)\)` 从 `schools_raw.json` 提取 |
| ② 教育部《全国普通高等学校名单》逐条核实的名校改名 | 28 | 现名必须**在`moe_schools.json`中真实存在**，否则剔除并告警 |
| 合并去重后 | **72**（其中 48 条能映射回 1367 院校库） | 24 条现名仍不在库内（如湖州师范大学/绍兴大学/榆林大学，库未收录） |

**导入时的映射优先级**（`import_major_score.py` 内，任一命中即停）：

1. 河南：`university_code.zfill(4)` → 河南招生代号索引
2. `university_name` → 全名/归一化名索引
3. `code2name[code]` → 校名索引（江西等自编代号省）
4. `alias.resolve(name)` → 现名再索引（`match_via="alias"`，可追溯）
5. 核心名（剥离尾部括号）兜底

**效果（与 `develop` 旧脚本同源复算）**：未匹配 **3,494 行（3.01%）→ 1,983 行（1.71%）**，
**救回 1,511 行**（`alias` 871 / `name` 396 / `code2name` 244）。

> **复算方法（可重复）**：取出 `git show origin/develop:data/scripts/import_major_score.py`，
> 与当前版脚本**在同一份 CSV 上各跑一次 `import_one`**，逐行比对 `school_id`。
> 全 6 文件 116,036 行结果：**救回 1,511 行 / 改错 0 行 / 丢失 0 行**。
>
> 另有 **23,355 行仅 `match_via` 标签被修正**：旧版写法是
> `nm = raw_name or code2name[code]` 再统一记 `match_via="name"`，
> 于是「**用代号反查校名**才匹配成功」的行被**错标成 `name`**；现已按真实路径如实标注
> （`name` / `code2name` / `alias`），`school_id` 未变。
>
> **旧版还有一处逻辑缺口（本次一并修掉）**：由于 `raw_name or ...` 的短路写法，
> **只要 `raw_name` 非空就永不查代号反查表**。而部分行原始校名缺后缀
> （如 `华北电力大学` → 库里是 `华北电力大学(保定)`），
> 代号才是权威归属 ⇒ 新版在「按名失败」后继续查代号，救回 **244 行**
> （华北电力大学(保定) 81 / 中国地质大学(北京) 72 / 中国石油大学(北京) 71 / 山东大学 20）。
> 校区归属得以保留（保定 ≠ 北京），**不是把分校并入母体**。

**剩余未匹配（1,983 行）原因分布**：院校库外 28 个 / 独立学院 22 个 / 军事院校 3 个 /
疑似数据脏值 2 个（`了喀什大学`、`和豫章师范学院`，首字异常，**不猜测不修补**）/ 分校区 1 个。
明细见 `data/schools/school_aliases.json` 的 `no_match_reason` 与 `stats` 段。

### 4.7 ★ `major_id` 回填（已实施）

**问题**：首期导入时专业库尚未建立，`major_id` **整列为 `null`** ——
而 `school_major_score` 的核心用途是「冲稳保推荐」，**没有专业维度就用不了**。

**解法**：以 `data/majors/majors.json`（教育部本科专业目录 2025 年，845 专业 + 93 专业类）
为映射表回填，脚本 `data/scripts/backfill_major_id.py`。

**映射规则**（4 级，任一命中即停；**不做同义词推断**）：

| 级 | 规则 | `via` |
|---|---|---|
| 1 | 专业名 == 目录**专业名** | `exact` |
| 2 | 专业名 == 目录**专业类名**（如「化学类」）→ 标 `kind=专业类` | `exact` |
| 3 | 去空白/换行 + 全角括号转半角后，命中专业名 | `normalized` |
| 4 | 同上规范化后，命中专业类名 | `normalized` |

**结果（实测）**：

| 项 | 行数 | 占比 |
|---|---:|---:|
| **已映射 `major_id`** | **113,836** | **98.10%** |
| ├ 映射到具体专业 | 103,019 | 88.78% |
| └ 映射到专业类（按类招生） | 10,817 | 9.32% |
| 未映射（保留 `major_id=null`） | 2,200 | 1.90% |

**★ `major_id` 的取值口径**（重要，② 建表时注意）：
- `kind=专业` → `major_id` = **6 或 7 位国标专业代码**（如 `120203K` 会计学）
- `kind=专业类` → `major_id` = **4 位专业类代码**（如 `1204` 公共管理类）
- 记录里同时写 `major_match` 对象（`kind/matched_name/class_code/class_name/menlei/via`）
  ⇒ **可追溯、可区分**，前端按 `kind` 决定展示「专业」还是「专业类」。

> ⚠️ **为什么专业类要单独标而不是当作专业**：
> 「化学类」「工科试验班类」是**按专业类招生**，不是具体专业。
> 若强行塞进 `major`，会污染专业库；当成专业处理，会让"这个专业"含义失真。
> 因此**保留原样、标明类型**，由下游决定怎么呈现。

**未映射 2,200 行的原因分布**（照实登记，**不补齐**）：

| 原因 | 去重名字 | 行数 |
|---|---:|---:|
| 试验班 / 大类招生（**非专业**，如「工科试验班」「理科试验班」） | 13 | 1,050 |
| 疑似**职业本科/专科**专业（如「大数据与会计」「人工智能工程技术」） | 65 | 670 |
| 院校自设专业名 / 其他（多为专科专业，如「现代物流管理」「护理」） | 76 | 480 |

> 📌 这 1.90% 的主体是**专科专业名**——而本库院校是**1367 所本科院校**，
> 这类专业本就**不在本科专业目录**内 ⇒ 未匹配是**正确行为**，不是漏采。
> 完整明细见 `_major_id_backfill_report.json` 的 `unresolved` 段（含每个名字的行数与原因）。

## 六、复现

```bash
# 扫描
python data/scripts/import_major_score.py --scan
# 全量导入
python data/scripts/import_major_score.py
# 单省单年
python data/scripts/import_major_score.py --province 河南 --year 2025
# 额外保留提前批 / 艺术类
python data/scripts/import_major_score.py --keep-prep --keep-art

# 解析教育部本科专业目录 → data/majors/majors.json
python data/scripts/parse_major_catalog.py
# 回填 major_id（依赖上一步的 majors.json）
python data/scripts/backfill_major_id.py
# 校验（三要素）
python data/scripts/validate.py data/school_major_score/school_major_score_2025_河南.json \
  --kind school_major_score
```

> （pending 数据须在界面如实标注），**不是错误**。真正的 ERROR 是 `school_id` 缺失的
> 1,983 行（客观缺失，已在 §4.4 / §4.6 说明根因）。
