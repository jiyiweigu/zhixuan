# 在线迁移复验报告（③ 徐）

> 日期：2026-10-14 ｜ 分支 `feature/xu` ｜ 环境：本机 PostgreSQL 16.15 + pgvector 0.8.6
> 目的：验证 **`alembic upgrade head` 在线模式**在 PostgreSQL 上是否可直接建库（此前只在 SQLite 验证过）。
> **本报告只做「复验 + 出补丁」，未改动仓库内任何文件。**

---

## 一、结论摘要

| 问题 | 结论 |
|---|---|
| 在线 `alembic upgrade head`（现状） | ❌ **不可用**，卡在 `0004`，报 `DatatypeMismatch` |
| 阻塞点数量 | **8 处 / 2 个迁移文件**（`0004` × 2、`0006` × 6） |
| 套上补丁后 | ✅ **`upgrade head` 成功**（7/7 迁移），**`downgrade base` 亦成功**（往返闭环） |
| 补丁后建出的库 vs 当前库 | ✅ **结构零差异**（356 列 / 88 索引 / 96 约束 / 26 序列 / `alembic_version=0007`） |
| 唯一残留差异 | 注释（`modify_comment` 132 处），**非结构**，见 §五 |

**根因**：这批迁移此前只在 **SQLite** 上跑过，SQLite 的宽松隐式转换把 3 类 PostgreSQL 会直接拒绝的写法掩盖了。

## 三、阻塞点清单（8 处，全部实测）

| # | 文件:行 | 现状写法 | PG 报错 | 触发时机 |
|---|---|---|---|---|
| 1 | `0004:30` | `batch_op.alter_column(... type_=sa.JSON())` | `column ... cannot be cast automatically to type json` | `upgrade` |
| 2 | `0004:38` | `UPDATE ... WHERE master_phd_points NOT LIKE '{%'` | `json` 类型不支持 `LIKE` | `upgrade`（在 #1 之后执行） |
| 3–8 | `0006:47 / 146 / 147 / 148 / 176 / 180` | `sa.Boolean(), ..., server_default=sa.text('0')` | `column is of type boolean but default expression is of type integer` | `upgrade`（`upgrade` 与 `downgrade` 皆会经手） |

**PG 侧实测证据**（本次独立复现，非推断）：

```sql
-- ① 布尔默认值：DEFAULT 0 被拒
CREATE TEMP TABLE _t2(b BOOLEAN NOT NULL DEFAULT 0);
-- ERROR: column "b" is of type boolean but default expression is of type integer
CREATE TEMP TABLE _t3(b BOOLEAN NOT NULL DEFAULT false);   -- ✅ CREATE TABLE

-- ② json 列不支持 NOT LIKE，但可显式转型
CREATE TEMP TABLE _t4(j JSON);
UPDATE _t4 SET j=NULL WHERE j IS NOT NULL AND j::text NOT LIKE '{%';   -- ✅ UPDATE 2
```

### 4.1 `20261012_0004_profile_master_phd_json.py`

要点：① 把「清空旧文本值」的 `UPDATE` **提到类型转换之前**（此时列还是 `VARCHAR`，`NOT LIKE` 合法）；
② `ALTER COLUMN ... TYPE JSON` 补 **`postgresql_using`**；③ 去掉 `batch_alter_table`（PG 上无需重建表，直接 `op.alter_column`）。

```diff
 def upgrade() -> None:
-    # ### commands auto generated by Alembic - please adjust! ###
-    with op.batch_alter_table('school_profile', schema=None) as batch_op:
-        batch_op.alter_column('master_phd_points',
-               existing_type=sa.VARCHAR(length=50),
-               type_=sa.JSON(),
-               nullable=True)
-
-    # ### end Alembic commands ###
     # 旧值为自由文本（如「硕士 60 / 博士 31」），JSON 列读取时会解析失败，
     # 统一置 NULL；真实数据由 tasks.md 2.5 重新入库后即为对象。
+    # 注：必须在列还是 VARCHAR 时执行，POSTGRES 下 JSON 列不支持 NOT LIKE。
     op.execute(
         "UPDATE school_profile SET master_phd_points = NULL "
         "WHERE master_phd_points IS NOT NULL AND master_phd_points NOT LIKE '{%'"
     )
+    op.alter_column(
+        'school_profile', 'master_phd_points',
+        existing_type=sa.VARCHAR(length=50),
+        type_=sa.JSON(),
+        nullable=True,
+        postgresql_using='master_phd_points::json',
+    )
 
 
 def downgrade() -> None:
-    # ### commands auto generated by Alembic - please adjust! ###
-    with op.batch_alter_table('school_profile', schema=None) as batch_op:
-        batch_op.alter_column('master_phd_points',
-               existing_type=sa.JSON(),
-               type_=sa.VARCHAR(length=50),
-               nullable=False)
-
-    # ### end Alembic commands ###
+    op.alter_column(
+        'school_profile', 'master_phd_points',
+        existing_type=sa.JSON(),
+        type_=sa.VARCHAR(length=50),
+        nullable=False,
+        postgresql_using='master_phd_points::varchar',
+    )
```

> 兼容性：`op.alter_column` 是 SQLAlchemy 通用 API，`postgresql_using` 为**方言专属 kwarg**，
> 在 SQLite 上被忽略——即打补丁后**两个方言都能跑**，不会破坏现有 SQLite 流程。

## 六、顺带发现（② 侧）

1. **注释漂移（非结构，但会让 `alembic check` 永远不干净）**
   在线迁移建出的库只有 **103** 条列注释，而 ORM 模型携带 **166** 条 —— 即
   `sa.Column(..., comment=...)` 并未在迁移里全部落到 PG。
   表现：全新库上 `alembic check` 恒报 132 处 `modify_comment`（本轮 `zhixuan` 是靠事后补注释才清零的）。
   建议：给迁移链补一条「按模型元数据同步 `COMMENT ON`」的迁移，或接受该差异并写进校验白名单。

2. **`backend/requirements.txt` 缺 `psycopg`**（连 PG 必需），建议补 `psycopg[binary]>=3.2`。

## 七、影响与建议

- **对比赛交付无影响**：`zhixuan` 生产库结构已被证明与「正确在线迁移」**完全等价**，可继续用于灌数。
- **对团队协作有影响**：任何队友照 `backend/` 文档在 PG 上跑 `alembic upgrade head` / `alembic downgrade` 都会**直接失败**。
- **建议顺序**：② 把 §四 的补丁应用到 `backend/alembic/versions/` → 我再对全新库复跑一轮 → 全绿后从任务清单勾掉 A5「在线可用」。
