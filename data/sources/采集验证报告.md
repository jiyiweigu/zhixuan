## 二、412 究竟是什么

对 `haeea.cn` 的响应体做了分析，返回的不是错误页，而是一段**混淆的 JavaScript**：

```html
<meta id="qAx7NxyxCzEz" content="mF.I.djI7k9fOGeLSAGD2AjM6..." r='m'>
<script>
  $_ts = window['$_ts']; if(!$_ts) $_ts={};
  $_ts.nsd = 86260;
  $_ts.cd = "qxmJrrQlEaQqDq33rS7cDqEMtaWoqrGqDqlWqGQqHu3h..."
</script>
```

**这是「瑞数（RiverSecurity）动态防护」的典型特征**：

| 特征 | 说明 |
|---|---|
| 返回混淆 JS 而非内容 | 需浏览器执行 JS 生成 Cookie 后才放行 |
| `$_ts.cd` 为加密串 | 每次请求动态变化，含浏览器指纹 |
| 首次请求必 412 | 拿到挑战 → 执行 → 带新 Cookie 重试才 200 |

### 2.1 已验证：改请求头无效

我尝试了**完整的浏览器请求头**（UA + Accept + Accept-Language + Sec-Fetch-* 全套）：

```
HTTP = 412    ← 仍然被拦
```

**结论**：它检测的不是请求头，而是**浏览器环境指纹 + JS 执行能力**。
`requests` / `httpx` 这类纯 HTTP 客户端**无法通过**。

## 四、三个对策方案

### 方案 A：无头浏览器（推荐用于批量采集）

用 **Playwright** 驱动真实浏览器内核，自动执行 JS 挑战。

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    page = browser.new_page()
    page.goto("https://www.haeea.cn/", wait_until="networkidle")
    html = page.content()          # ← 拿到真实内容
    browser.close()
```

| 优点 | 缺点 |
|---|---|
| 稳定、通用、能过 JS 挑战 | 需下载浏览器内核（约 150MB） |
| 可处理动态渲染页面 | 速度慢于纯 HTTP |

> 🔴 **重要**：装 Playwright 属于**新增第三方依赖**，按 `development-guide.md` 第六节，
> **须先在站会申报用途与许可**（Playwright 为 Apache-2.0，宽松许可）。

### 方案 B：人工下载附件 + 脚本解析（推荐用于核心数据）

官方数据**多以 PDF / Excel 附件形式发布**。人工下载后，脚本只负责解析。

| 优点 | 缺点 |
|---|---|
| 完全合规、不触发风控 | 需人工介入 |
| 稳定、可复核（原始文件存档） | 不适合高频更新 |

> 💡 **这反而最贴合实际**：一分一段表、控制线这类数据**每年只发布几次**，
> 人工下载一次即可，没必要为它建爬虫。

### 方案 C：降低频率试探（不推荐）

⚠️ 不推荐作为主方案。且**必须事先获得队长许可**。
