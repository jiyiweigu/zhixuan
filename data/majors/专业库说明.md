## 二、★ 一个必须记录的坑：专业代码不都是 6 位

首次解析只得到 **840 条**，比官方口径 845 **少 5 条**。

**排查过程**（不是猜的，是逐项排除）：
1. 检查专业代码重复 → 0 条重复 ✅
2. 检查 93 个专业类是否都在 → 全在，且**没有空类** ✅
3. 检查每个专业类下的代码序号是否断层 → **0 处断层** ✅
4. 检查 PDF 印刷页码 ∈ [46,74] 连续、30 页无缺 → **无缺页** ✅

⇒ 说明 PDF 是完整的，**是我们的正则漏了**。

**根因**：`外国语言文学类（0502）` 下有 **5 个专业使用了 7 位代码**：

| 专业代码 | 专业名称 |
|---|---|
| `0502100T` | 语言学 |
| `0502101T` | 塔玛齐格特语 |
| `0502102T` | 爪哇语 |
| `0502103T` | 旁遮普语 |
| `0502104TK` | 区域国别学 |

原来的正则写死 `^(\d{6}[TK]{0,2})`，**7 位代码全部漏掉**。

**修复**：放宽为 `^(\d{6,7}[TK]{0,2})`，同时把 `class_code` / `menlei_code` 的取法
从「写死 `code[:4]` / `code[:2]`」改为「**先剥离 T/K 后缀再看位数**」——
否则 `0502104TK` 会被 `rstrip` 后取错位。

> 📌 **教训**：不要假设编码位数固定。**用"总数对不对得上"做校验，而不是假设格式**。

## 三、字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | string | 专业代码，**原样保留**（含 T / K 后缀，6 或 7 位） |
| `code_len` | int | 剥离 T/K 后的位数（6 或 7） |
| `name` | string | 专业名称 |
| `code_type` | string | `基本专业` / `特设专业` / `国家控制布点专业` / `特设专业+国家控制布点` |
| `is_special` | bool | 是否特设专业（代码带 `T`） |
| `is_state_controlled` | bool | 是否国家控制布点（代码带 `K`） |
| `class_code` | string | 专业类代码（4 位） |
| `class_name` | string | 专业类名称，如 `外国语言文学类` |
| `menlei_code` | string | 学科门类代码（2 位） |
| `menlei` | string | 学科门类名称，如 `文学` |
| `degree_note` | string \| null | 学位授予特别说明（原 PDF 的「注：…」），**96 条有该注** |

### 3.1 代码后缀规则（教育部定义，**不可自行解读**）

- **无后缀** = 基本专业（学科基础成熟、需求稳定、布点较多）
- **`T`** = 特设专业（满足经济社会发展特殊需求）
- **`K`** = 国家控制布点专业（涉及国家安全、特殊行业）
- **`TK`** = 兼具上述两者

> ⚠️ 本脚本**不剥离后缀**。`code` 字段原样入库，需要纯 6 位码时由 ② 或 ④ 自行切片。

## 六、关于「845 种专业」与「6.28 万个专业布点」

教育部答记者问提到两个数字，**含义不同，不要混用**：

| 数字 | 含义 | 本库是否收录 |
|---|---|---|
| **845 种专业** | 全国本科**专业种类数**（目录内的"菜名"） | ✅ **本库 = 845** |
| **6.28 万个专业布点** | 各高校**实际开设的专业点**总数（"哪家馆子做这道菜"） | ❌ 不在本库 |

> 本库是**专业目录**（种类），不是**专业布点**（高校×专业的组合）。
> 「某校开设某专业」属于 `school_major_score` / 后续 `school_major` 的范畴。

### 为什么是 938 行（845 + 93）

录取分库 116,036 行中，**10,817 行是「按大类招生」**，其专业标识是 **4 位专业类代码**（如 `0809`）。
若 `major` 表只有 845 个专业行，这 10,817 行**无处可指**。
补入 93 个类行后，全量实测分布为：

```
命中专业码 103,019  +  命中类码 10,817  +  空 2,200  =  116,036，落空 0
```
