## 〇、一句话结论

**链路只差「最后一跳」，而且这一跳现在被 9 个硬阻塞卡住。**
`data/scripts/` 里**没有任何脚本写数据库**（零 `psycopg` / 零 `INSERT`）——它们只把原始层规范化成 `data/staged/*.jsonl`。
真正会写库的代码只有 `backend/app/services/*_seed.py`（② 的域），而它**现在只读演示数据**。

⇒ 「转换和入库」实际是**两件事、两个归属**：
- **转换**（③ 主责）：raw → JSONL → 改成「表结构可直接吃」的形态 → 消掉 9 个硬阻塞。
- **入库**（`建库任务清单` C 组 = **② 主责**，③ 配合）：写 loader 按外键顺序灌 + 跑校验。

## 三、执行三步

### Step 1（③ 主责，可立即做，不越界）——「物理消除硬阻塞」

把 staged JSONL 与各产物 JSON 里的**逻辑键换成物理 id**：

```
source_id : "SRC-GAOKAO-COMPASS"  ──(mappings/source-id-map.json)──▶  3
major_id  : "120203K"             ──(mappings/major-code-map.json)──▶ 731
school_id : 业务键 code/名称       ──(school.code 直连, R1)────────▶  id
```

- 映射表**找不到的取值 → 显式报错、不猜**（口径归一映射已是这个行为）。
- 产物落在 `data/staged_golden/`（不覆盖原 staged，保留可回溯）。

### Step 2（归属：`建库任务清单` C 组 = **② 主责**）——「按外键顺序灌」

**唯一可行顺序**（FK 依赖）：
```
source ─▶ school ─▶ major ─▶ score_segment ─▶ school_major_score
       └▶ pathway ─▶ pathway_region ─▶ pathway_eligibility ─▶ province_exam_rule
       └▶ enrollment_rule ─▶ school_profile ─▶ school_life
```
- **幂等**：按业务键 `ON CONFLICT DO NOTHING`（或先查后插），重复执行行数不变。
- **来源校验前置**：三要素缺失的行**不入库**（同 `app/core/dataset.py` 口径）。
- 归属说明：`建库任务清单` 把 C1–C5 定为 ② 主责；若 ② 长期不到位，③ 可顶上
  （**不违反铁律**——「建表 / Alembic = ②」已闭环，「让库里有数据 = ③」，见 MEMORY 铁律）。

### Step 3（③ 主责，C6）——「灌完即验」

```bash
python data/scripts/validate.py                       # 全量三要素校验
python backend/test_*.py                              # 13 个后端测试
psql -c "select count(*) from school" ...             # 行数与 JSON 对齐
```
