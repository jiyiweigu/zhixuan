# Proposal

## Why

高考志愿填报存在三个突出问题：院校与专业信息高度分散、推荐结果不可验证（用户不知道结论从何而来）、以及对**多元升学途径**（国家/地方/高校专项、强基计划、艺术体育、军警招飞、公费师范、定向培养等）覆盖不足——而后一类机会恰是信息弱势与农村家庭最容易错过的。

团队需在 **2026-10-23 23:59:59** 前交付一款可运行、可溯源、覆盖多元升学途径的志愿填报辅助 Web 应用，并同步产出参赛材料。本变更即为该产品的完整能力定义。

## What Changes

- 新增**用户账号与鉴权**：注册/登录、JWT 会话、密码加盐哈希、最小化采集个人信息。
- 新增**考生档案**：省份、科类、选科、分数与位次、户籍类型、专项资格、意向城市/专业、学费预算，作为个性化推荐的档案基础。
- 新增**升学途径目录与路径资格自检**：覆盖 26 类升学途径；依据户籍类型、户籍所在县、学籍年限与专项实施区域名单，判断用户可报考的专项与特殊通道（由显式规则引擎实现，不使用大模型）。
- 新增**可溯源智能问答**：检索增强生成（混合检索 + 重排 + 受限生成），每条结论绑定来源片段，并输出高/中/低三级置信度。
- 新增**志愿方案与推荐**：冲—稳—保方案生成、院校优先/专业优先/城市优先三种策略、梯度与退档风险预警。
- 新增**院校与专业库检索及院校画像**：学费、办学实力、师资、校区、生活信息；生活类信息强制标注来源类型与可靠性等级。
- 新增**知识库管理端**：语料管理、索引管理、人工审核工作台、升学途径与资格规则维护、数据统计。
- 确立**数据分层策略**：P0 = 普通批 + 三大专项（先河南后江西）；P1 = 强基/艺术/体育/军警招飞/公费师范/定向；P2 = 其余途径仅提供途径字典与规则，录取数据如实标注"规划中"。
- 产出**参赛材料**：作品介绍文档、演示视频、原创性与知识产权声明、AI 工具使用情况说明。

## Capabilities

### New Capabilities
- `user-account`: 用户注册、登录与鉴权，账号安全与个人信息最小化采集。
- `candidate-profile`: 考生档案的建立与维护，为资格自检与个性化推荐提供输入。
- `pathway-eligibility`: 多元升学途径目录与路径资格自检，输出可报考通道及其规则依据。
- `knowledge-qa`: 可溯源智能问答，含混合检索、受限生成、引用溯源与置信度分级。
- `volunteer-plan`: 志愿方案生成与多策略推荐，含梯度划分与风险预警。
- `school-catalog`: 院校与专业库检索及院校画像，含信息来源与可靠性标注。
- `knowledge-base-admin`: 知识库管理端，含语料与索引管理、人工审核闭环、途径规则维护与统计。

### Modified Capabilities
无。本变更首次建立上述能力，不修改任何既有能力。

## Impact

- **新增代码**：前端（Vue 3 用户端 + 管理端，同工程不同路由）、后端（FastAPI 服务 + 资格规则引擎 + RAG 链路）、数据管道（采集/清洗/结构化/向量化）。
- **新增数据表**：院校/专业/录取分/一分一段/招生章程/学科评估、升学途径/资格规则/专项区域、用户账号/档案/收藏/方案、院校画像/生活信息、知识文档/切片/问答日志/审核任务。
- **外部依赖**：PostgreSQL 16 + pgvector、bge-small-zh-v1.5、bge-reranker-base、通义千问 API（模型名与版本须在材料中如实标注）。
- **数据来源**：河南省教育考试院、江西省教育考试院、阳光高考平台、教育部公开数据、高校招生章程与就业质量报告等公开渠道。
- **合规约束**：所有事实性结论须可溯源；生活类信息须标注来源与可靠性；界面与文档须展示免责声明；AI 工具使用情况须如实披露。
- **交付形态**：本地可运行 Demo + 3–5 分钟演示视频 + 作品材料。
