## Context

产品已有 RAG、方案和来源约束，但“竞争热度研判”尚未进入契约。历史数据只能支持趋势分析，不能推导实际报名人数或录取概率。算法负责人需要确定性、可评测的输出；大模型只能解释证据，不能改变计算结果。

## Goals / Non-Goals

**Goals:**

- 固化问答的检索、生成、引用、置信度、降级和审核链路。
- 固化方案算法与 AI 解释的职责边界。
- 提供可审计的竞争热度趋势计算和展示结构。

**Non-Goals:**

- 不预测实际报名人数、录取概率或保证录取。
- 不让大模型参与资格判定、位次计算、方案排序或趋势等级判定。
- 不在本变更中接入爬虫或确定具体模型供应商。

## Decisions

1. **RAG 编排分层**：query rewrite、retrieval、rerank、generation、citation、confidence、review 分为独立服务，便于单测和降级。
2. **证据优先生成**：生成器只接收召回片段；输出必须包含引用编号，证据不足返回固定兜底文案。
3. **趋势由统计服务计算**：按同一省份、年份、批次、途径、院校专业口径对齐最低位次、计划数和来源；模型不参与标签判定。
4. **趋势是附加字段**：`trend_analysis` 挂在推荐项上，不改变冲稳保排序；前端使用醒目标识和免责声明。
5. **不可比即拒判**：少于两年有效数据、来源缺失、口径变化或计划变化无法解释时，输出 `insufficient_data`。
6. **解释受限**：大模型输入只包括结构化算法结果和引用数据；不得生成输入中没有的新数字、年份或结论。

## Risks / Trade-offs

- [历史数据与今年政策不一致] → 展示年份、来源、可比性说明，使用“趋势研判”措辞。
- [用户误解趋势为录取概率] → 使用固定免责声明，禁止承诺性表述。
- [模型解释偏离算法] → 校验趋势枚举、数字和引用；校验失败时展示结构化结果。
- [数据量不足] → 输出“趋势暂不可判断”，不调用模型补写。

## Migration Plan

1. 先实现趋势计算、DTO 和 Mock，不接入模型。
2. 接入真实历史数据后运行可比性校验和评测。
3. 再接入受限解释生成，保留结构化结果作为降级路径。
4. 通过前端开关逐步启用，异常时可关闭解释但保留推荐。

## Open Questions

- 趋势阈值由 30 条以上历史样本和回测结果校准，不在本变更中凭经验固定。
- 首期是否按院校专业粒度还是志愿组粒度展示，由数据负责人根据可用数据决定；DTO 同时保留 target_type。
