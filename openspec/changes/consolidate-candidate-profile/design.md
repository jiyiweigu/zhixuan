## Context

当前项目已有手机号以外的用户名登录示例、简化 Profile DTO 和多个使用硬编码条件的用户页面。已归档的 `candidate-profile` 规格和 API Contract v1.1 已定义选科、体检、预算等字段，但仍需要明确“档案唯一事实来源”的流程和实现边界。本变更依赖既有认证、资格约束和推荐接口，不重新实现规则引擎。

## Goals / Non-Goals

**Goals:**

- 注册后以向导采集可用于资格判断和志愿推荐的完整档案。
- 用一个版本化 Profile 快照驱动资格、推荐、风险体检和专业适配。
- 区分必填基础字段、可跳过但强影响字段、未知状态和缓存失效。
- 让手机号、敏感档案、访问权限、注销删除和日志脱敏有明确边界。

**Non-Goals:**

- 不在注册时采集身份证、准考证、完整体检报告或其他非必要证件。
- 不把档案向导变成招生规则判定器；判定仍由后端资格引擎完成。
- 不在本变更内新增提前批规则或真实招生数据。
- 不要求用户首次注册一次填完全部敏感字段；允许跳过并以待核验状态继续浏览。

## Decisions

### 1. 注册与档案分离

注册只创建手机号账号、密码哈希和会话；成功后返回 `profile_completed`/`next_step`，前端进入 `/profile?onboarding=1`。已有用户登录后根据档案完成度决定是否提示补全，不强制每次登录重复填写。

手机号采用 E.164/项目约定格式校验并唯一；密码永不明文存储。验证码服务未接入时只保留可替换接口和 Mock，不在前端硬编码真实验证码。

### 2. 两段式档案模型

第一段为个性化判断的基础门槛：省份、年份、考试类型、首选科目、再选科目、分数、位次、首期批次。第二段为强影响条件：色觉、视力、身高体重、乙肝、听力/嗅觉/口吃、学费预算、户籍学籍、专项标记、意向和调剂偏好。第二段可跳过，但缺失字段必须显示影响范围。

### 3. 单一读取入口

下游页面不再在组件中写死省份、分数或科类；统一从 profile store/API 获取 Profile 快照，调用资格/推荐接口时由服务端优先使用登录档案。游客模式仅允许明确提交的临时 Profile，不写入账号档案。

### 4. 完成度不是通过状态

完成度按字段组计算，并返回 `missing[]` 与 `impact[]`。基础字段缺失时阻止个性化请求；体检、预算等可选字段缺失时允许请求，但服务端必须返回 unknown/待核验，不得默认通过。

### 5. 更新即失效

Profile 保存成功后以 `updated_at` 或内容指纹作为版本键，清除资格、推荐和风险体检缓存。并发保存采用服务端最后写入前的版本校验或明确覆盖策略，避免旧页面覆盖新档案。

### 6. 敏感资料最小化

体检只存规则需要的结构化结论，不上传原始报告；日志和错误响应不得打印完整 Profile；用户注销时删除或匿名化账号与档案关联数据。前端在第二段开始前展示用途说明和可跳过提示。

## Risks / Trade-offs

- [一次采集字段较多，用户可能中途退出] → 两段保存、自动恢复草稿、显示完成度和缺失影响。
- [体检/预算缺失被误解为合格] → `null` 统一进入 unknown，UI 使用待核验标签，接口测试锁定。
- [旧页面仍使用硬编码条件] → 在 API 层和代码审查中禁止页面直接传固定考生条件；增加核心流程 smoke test。
- [手机号认证与现有用户名 Mock 不兼容] → 保留响应包结构，新增手机号字段并提供迁移/兼容期；真实登录联调前冻结 DTO。
- [敏感档案泄漏] → 访问控制、日志脱敏、最小采集和注销删除作为验收项。

## Migration Plan

1. 扩展认证与 Profile DTO，先更新契约、类型和 Mock。
2. 建立手机号唯一字段、档案新字段和完成度计算；保留旧演示用户的兼容映射。
3. 改造注册后路由与 Profile 两段式向导，移除资格/推荐页面中的硬编码条件。
4. 将资格、推荐、风险体检改为读取档案快照，并在保存后清理缓存。
5. 完成空档案、部分档案、完整档案、清空字段、注销删除和未授权访问测试。

回滚时保留已有认证响应兼容字段，关闭注册后强制引导即可；档案新字段使用可空迁移，避免回滚旧版本时破坏旧用户记录。

## Open Questions

- 短信验证码供应商和正式发送频控尚未确定，本提案只冻结接口位置与前端流程。
- “高考年份”当前 API Contract 尚未作为 Profile 字段明确冻结，需要在实现前补入统一字段名。
- 是否要求基础字段全部完成后才能进入 `/plan`，还是允许展示无个性化空壳，需要产品最终确认；本设计默认基础字段未完成时不生成个性化方案。
