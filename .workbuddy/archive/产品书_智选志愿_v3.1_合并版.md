## 二、选题背景与价值

### 2.1 问题背景
志愿填报是每年千万级考生家庭的共同难题：院校、专业、历年分数线、位次、录取规则等信息高度分散，考生与家长缺乏结构化检索与对比手段，决策常依赖碎片化经验。市面工具虽多，但普遍存在三点不足：一是推荐结果"黑箱化"，用户无法验证结论从何而来；二是**多聚焦普通批次，对专项计划、强基、艺术体育、军警招飞、公费师范等多元升学途径覆盖不足，而这些恰是信息弱势家庭最需要、也最容易错过的机会**；三是缺乏对志愿梯度、退档风险的主动提示。

## 三、产品概述与核心功能

### 3.1 产品定义
以权威公开招生数据构建**结构化知识库 + 向量知识库**，通过检索增强生成（RAG）技术，为用户提供"分数 → 位次 → 院校 → 专业 → 升学途径"的可溯源问答、志愿方案辅助分析与院校认知服务。

### 3.2 用户系统（本版新增）
用户系统不只是账号管理，更是**个性化推荐的档案基础**——它使"专项资格自检""城市/专业优先"成为可能。

| 功能 | 说明 | 优先级 |
|---|---|---|
| 注册 / 登录 | 用户名 + 密码（密码加盐哈希存储）；支持游客体验模式 | P0 |
| 考生档案 | 省份、科类（普通/艺术/体育）、首选科目（物理/历史）、再选科目、分数、位次、**户籍类型（城镇/农村）**、**专项资格**、意向城市、意向专业、学费预算 | P0 |
| 收藏与关注 | 收藏院校、专业、院校专业组，支持导出 | P1 |
| 志愿方案管理 | 保存/命名多套志愿草表，随时编辑 | P0 |
| 问答历史 | 按会话保存问答记录，可回溯 | P1 |
| 院校对比 | 多所院校关键指标并排对比 | P1 |

**档案的核心作用**：户籍类型与专项资格是判断用户"**能否报考国家/地方/高校专项**"的依据；选科与位次决定可报专业范围；意向城市/专业驱动推荐排序。用户填一次档案，全站个性化。

### 3.3 多元升学途径覆盖（核心创新点 I6）
平台覆盖 **26 类升学途径**（完整清单见附录 D），并为每类提供：所属批次、报考条件、面向人群、关键时间节点、对应录取数据。

**最具差异化的是"路径资格自检"**：用户填写户籍类型、户籍所在县、学籍年限后，系统按内置规则自动判断"我能报考哪些专项/特殊通道"。例如河南考生输入"农村户籍、户籍在 XX 县"，系统提示可报考地方专项；若该县属于国家专项 38 县名单，则额外提示可报考国家专项。**这是通用工具几乎不做、而信息弱势家庭最需要的功能。**

> 河南三大专项关键差异（已在平台规则中实现）：
> - **国家专项计划**：实施区域为 38 个县，要求本地连续 3 年户籍与学籍，**不要求农村户口**；
> - **地方专项计划**：面向**全省农村**户籍考生；
> - **高校专项计划**：实施区域为 53 个县，要求**实施区域农村**户籍；2026 年起不再组织校测，依据高考成绩与志愿录取。

### 3.4 推荐策略与院校画像（本版新增）

**推荐策略（用户可切换）**
| 策略 | 说明 |
|---|---|
| 院校优先 | 按院校层次（985/211/双一流）、学科实力排序 |
| 专业优先 | 按目标专业的学科评估、一流本科专业建设点排序 |
| 城市优先 | 按意向城市/经济区域排序，支持多城市优先级 |

三种策略均在同一"冲—稳—保"框架下调整排序权重，且**每条推荐必须标注依据与数据来源年份**。

**院校画像（帮助学生提前了解学校）**
| 信息类别 | 内容 | 来源与合规处理 |
|---|---|---|
| 学费 / 住宿费 | 学费标准、住宿费 | 省招生专业目录、招生章程（**官方公开，高可靠**） |
| 办学实力 | 办学层次、硕博点数量、国家级一流本科专业数、师资规模 | 学校官网、教育部公开数据（**官方公开，高可靠**） |
| 师资教学 | 师生比、国家级教学名师、一流课程数 | 官方公开指标（**不做教师个人评价，规避隐私与名誉风险**） |
| 校区与地址 | 校区分布、所在城市 | 学校官网（**官方公开**） |
| 生活信息 | 宿舍条件、食堂、校园环境、交通 | 官网公开 + 公开网络整理（**非官方，必须标注来源与时效，默认折叠并提示"仅供参考"**） |

> **合规红线**：生活类信息主观性强、时效性差，一律通过 `source_type` / `reliability` 字段强制标注来源与可靠性等级；非官方信息前端默认折叠展示并附提示，不作为择校依据。

### 3.6 核心业务流程
```
用户注册 → 填写考生档案（含户籍类型/所在县）
        │
        ├─► 路径资格自检：输出"可报考的专项/特殊通道"清单（附规则依据）
        │
        └─► 提问 / 选择推荐策略
              → Query 改写（多轮场景）
              → 混合检索（向量 + BM25，按途径/省份过滤，RRF 融合）
              → 重排序 Rerank → 大模型受限生成（仅依据检索片段）
              → 答案 + 来源标注 + 置信度 → 前端展示
                                          → 低置信/涉分数线类答案自动进入人工审核队列
                                          → 审核结果回流知识库（修正/补数据/重建索引）
```

    │               │               │

### 5.2 技术选型（已冻结，见第 11 章）

| 层次 | 选型 | 选择理由 |
|---|---|---|
| 前端 | Vue 3 + TypeScript + Vite + Element Plus + ECharts | 组件库成熟，无美术基础也能产出规范界面 |
| 后端 | Python 3.11 + FastAPI + SQLAlchemy 2.0 + Pydantic v2 | RAG 生态成熟，自动生成 OpenAPI 便于并行 |
| 鉴权 | JWT + 密码加盐哈希（bcrypt / argon2） | 轻量、安全、易实现 |
| 数据/向量 | PostgreSQL 16 + pgvector | 结构化与向量同一库，降低部署运维成本 |
| 检索 | pgvector (HNSW) + BM25，RRF 融合，支持按省份/途径过滤 | 兼顾语义与精确匹配 |
| Embedding | bge-small-zh-v1.5（512 维） | 开源中文模型，CPU 可运行 |
| Rerank | bge-reranker-base | 开源中文重排模型 |
| 大模型 | 通义千问（qwen-plus / qwen-max）API | 中文稳定，国内可直连；模型名须如实标注 |
| 部署 | uvicorn + 本地/服务器运行 | 答辩采用本地运行 + 录屏 |

### 5.3 需求与业务逻辑（分类评价重点 ①）
业务逻辑明确为：用户注册并填写考生档案 → 系统执行路径资格自检、提供提问与多策略推荐 → 问答经"改写—召回（按省/途径过滤）—重排—受限生成—溯源—置信度"输出 → 低置信与高风险答案进入人工审核 → 审核结果回流知识库。业务规则（冲稳保梯度、位次换算、单科限制、专项资格判定）均在代码中显式实现并留痕，非模型自由发挥。

### 5.4 核心功能与系统架构（分类评价重点 ②）
见 3.5 功能清单与 5.1 架构图。系统分**数据层（结构化库 + 向量库）、服务层（用户认证/问答编排/检索/资格规则引擎/审核/统计）、应用层（用户端 + 管理端）**，层次清晰、职责分离。

### 5.5 交互体验（分类评价重点 ③）
- 问答结果"答案正文 + 溯源卡"双栏布局，来源可一键展开原文。
- 志愿方案以"冲/稳/保"三档卡片呈现，每档标注判断依据（位次差、年份、来源）。
- **路径资格自检**以"我能报哪些"清单式呈现，每条附规则依据（如"你所在县属于国家专项 38 县名单"）。
- **推荐策略**以顶部 Tab 一键切换，结果实时重排并标注差异原因。
- **院校画像**以标签页组织（概况/学费/师资/生活），生活类信息默认折叠并标注来源可靠性。
- 低置信答案前置黄色提示条；风险项以醒目标签标注。
- 管理端审核工作台采用"待审列表 + 原文对照 + 一键通过/修正/驳回"三步式操作。

### 5.6 运行稳定性（分类评价重点 ④）
- 检索/生成超时降级：大模型超时返回"基于检索片段的原文摘要"，保证不空答。
- 索引重建为增量任务，失败不影响线上问答。
- 关键链路（注册、入库、检索、资格判定、审核）均有日志记录与异常捕获。
- 测试负责人按第 20 章验收清单执行回归。

### 5.7 数据安全（分类评价重点 ⑤）
- **账号安全**：密码加盐哈希存储（不可逆），会话采用 JWT；登录失败次数限制。
- **最小化采集**：不采集身份证号、准考证号、手机号非必填；用户输入的分数仅用于当次会话与用户本人档案。
- **隐私合规**：提供隐私政策与用户协议；支持账号注销与数据删除。
- **权限隔离**：管理端需登录鉴权，问答与审核操作留痕可追溯。
- **部署安全**：数据库本地/自有环境部署，不上传第三方。
- **第三方资源与数据来源**全部列明（见第七章）。

### 5.8 应用价值（分类评价重点 ⑥）
面向高考考生家庭的教育公益类工具，具备科技普及、教育服务与**教育公平**价值——尤其帮助农村与信息弱势家庭发现专项计划等升学通道。架构支持扩展至更多省份与更多学段（考研、专升本），具备持续迭代与推广可能。不以商业化作为目标。

## 十四、RAG 链路规格（算法负责人严格执行）

| 环节 | 规格 |
|---|---|
| 切片 | 语义段落切分，chunk_size = 512 tokens，overlap = 64；结构化表数据经"文本模板"转换后入库，并携带 `province` / `pathway_id` 元数据 |
| 向量化 | bge-small-zh-v1.5，512 维，入库前 L2 归一化；索引 HNSW |
| 召回 | 向量 top-50 + BM25 top-50，**先按 province / pathway 过滤** → RRF 融合 → top-20 |
| 重排 | bge-reranker-base → top-8 |
| 生成 | 受限提示词：仅使用给定片段作答；每条结论以 `[n]` 标注引用；片段无依据时必须回复"知识库暂无相关数据，建议查阅官方渠道"；temperature ≤ 0.3 |
| 溯源输出 | `citations: [{ chunk_id, source_name, source_url, year, snippet }]`，前端强制渲染 |
| 置信度 | rerank 最高分 ≥ 阈值A 且命中结构化数据 → high；命中其一 → medium；均未命中或分数低于阈值B → low。low 时前端提示"建议人工核实"且自动入审核队列 |
| 查询改写 | 多轮场景先做指代消解，生成完整独立问句再检索 |
| 路径维度 | 用户已填档案时，检索默认按用户省份过滤；提问涉特定途径时按途径过滤 |
| 降级 | 大模型超时/失败 → 返回检索片段原文摘要，标注"AI 生成暂不可用" |

**资格判定（非 RAG）**：由规则引擎实现——输入 `province, household_type, home_county, 学籍年限` → 比对 `pathway_eligibility` 与 `pathway_region` → 输出可报路径 + 每条规则依据 + 来源。

**评测要求**：算法负责人须在 D13 前产出一份小规模评测（≥ 30 条标注问答），统计检索命中率与溯源覆盖率；另须对资格判定准备 ≥ 20 条测试用例（含边界：非农村户籍、县不在名单内、学籍年限不足）。

## 十五、功能模块详细规格与验收标准

| 功能 | 输入 | 处理要点 | 输出/验收标准 |
|---|---|---|---|
| F1 智能问答 | 自然语言问题 | 走第十四章 RAG 链路 | 返回答案 + citations + confidence；响应 ≤ 8s |
| F2 答案溯源卡 | citations | 前端渲染来源名称/年份/URL/原文 | **每条结论均可点开原文；无 citations 的结论不得展示** |
| F3 院校专业检索 | 省份/层次/学科/分数区间 | 结构化 SQL 查询 | 分页正确，条件组合生效 |
| F4 志愿方案生成 | 分数、位次、选科、省份、策略 | 位次差法划分冲/稳/保；依据须为可核验历史数据 | 三档方案，每档附依据与来源年份；无来源不得输出承诺性表述 |
| F5 路径资格自检 | 户籍类型、户籍所在县、学籍年限、省份 | 规则引擎比对实施区域与资格规则 | 输出可报路径清单，**每条附规则依据与来源**；≥ 20 条用例通过 |
| F6 升学途径查询 | 途径 id / 分类 | 读途径字典 | 批次、条件、时间、面向人群完整 |

| F8 院校画像 | school_id | 读 profile / life | 官方信息与生活信息分开展示；生活信息标来源与可靠性 |
| 用户注册登录 | 用户名/密码 | 哈希存储、JWT 签发 | 密码不可逆；重复注册拦截 |
| 考生档案 | 各类条件 | 校验并存储 | 保存后可驱动自检与推荐 |
| A3 审核工作台 | 待审答案 | 状态机 | 审核写入 `review_task`，可筛选、可追踪 |

**全局验收红线**：
1. 任何事实性结论**必须**带来源，否则不得展示（I1 硬性落地）。
2. UI 与文档**必须**展示免责声明。
3. 涉分数线、录取规则的答案默认进入审核队列。
4. 资格判定结论**必须**可追溯到具体规则与来源，禁止"AI 猜测资格"。
5. 用户密码明文不得出现在日志或数据库中。

## 十六、审核工作台流程（状态机）

```
AI 生成答案
   │
   ├─ confidence = low ──────────► 自动入队 pending
   └─ 涉分数线/录取规则/升学途径资格 ─► 自动入队 pending
                                        │
                    ┌───────────────────┼───────────────────┐
                    ▼                   ▼                   ▼
              approved(通过)      corrected(修正)      rejected(驳回)
                    │                   │                   │
                    │              写入修正后答案        通知数据负责人补数据
                    │                   │                   │
                    └──────────► 沉淀为可信知识 ◄──────────┘
                                 (重建索引后生效)
```

审核记录须完整留痕（审核人、时间、动作、意见），作为 AI 使用评价的佐证材料。
