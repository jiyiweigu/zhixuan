## 三、本次修复的最大问题：院校层次标记几乎为空

院校层次（985/211/双一流）是**「冲稳保」与院校筛选的核心维度**，但原来三份数据谁都没给全：

| 来源 | 覆盖面 | 结果 |
|---|---|---|
| 张的院校库 | 只有河南本地 183 校 | 匹配上 139 所，`is_985` 命中 **0**、`is_211` 命中 **3** |
| 徐的院校库 | 1,367 所 | 该字段**根本不存在** |
| 徐的软科榜 | 594 校（tags 标了 985/211/双一流） | 只有 37 / 97 / 112，**低排名的 211 不在榜内**（如西藏大学、石河子大学） |

也就是说：整合前的合并产物里，清华北大都不是 985。**现已按教育部公开名单补齐**：

| 标记 | 修复前 | 修复后（行数） | 去重后母体数 |
|---|---:|---:|---:|
| `is_985` | 0 | **52** | 45 |
| `is_211` | 3 | **135** | 120 |
| `dual_class` | 8 | **171** | 152 |

行数（52/135/171）> 母体数（45/120/152）是**正常且正确**的：招生库会把「中外合作办学」「分校区」单列成独立招生单位，它们与母体共用国标代码、发母体文凭，继承层次是对的。

**交叉验证（脚本内断言 + 独立核验脚本，全部通过）**：
- 教育部名单的 39/112/147 所，在 1367 所库里**缺席 0 所**；
- 软科榜标注过的院校，**没有一所**在名单里找不到（说明名单是软科的严格超集）；
- 河南 985 **= 0**（硬事实）；河南 211 全部属郑州大学（含其惠灵顿学院、中外合作办学项目）；河南双一流 = 郑州大学 + 河南大学；
- 不存在「`is_985` 但非 `is_211`」「`is_211` 但非双一流」的行。

## 四、特别说明：校名形状相同、语义相反的两类

「母体校名 + 后缀」这个形状对应两种完全不同的东西，**字符串区分不了**，所以一律不自动推断：

| 类型 | 例子 | 是否继承母体层次 |
|---|---|---|
| 非独立法人的分校区 / 直属医学院 | 复旦大学医学院、浙江大学医学院、山东大学威海分校、东北大学秦皇岛分校、中国石油大学(北京)克拉玛依校区 | **继承**（发母体文凭）—— 已逐个核实，共 5 所，登记在 `school_tiers.json` 的 `inherit.map` |
| **独立学院** | 厦门大学嘉庚学院、电子科技大学中山学院、南京理工大学紫金学院…… | **不继承**（独立法人、独立文凭、独立国标代码）—— 已核实 34 所，登记在 `inherit.known_not_inherited`，刻意不标 |

一个可操作的判别法：**共用国标代码 → 自动继承**（脚本按代码匹配，无需登记）；**有独立国标代码 → 才需要人工确认**。

## 六、装载怎么做（给后端/数据库的交接）

**关键结论：不需要建新库。** 后端 `backend/alembic` 已有 30 张表（含契约 §8.7 的 7 张规则表），缺的只是把上面这份数据写进去的通道。

1. 迁移已就绪：`20261013_0008_merge_ready.py`（放宽 `school_major_score.school_id`/`major_id` 为可空、`school` 加层次列、加 `group_code`/`same_score_count` 等）+ `20261014_0009_school_major_score_identity.py`，均已在 develop。
2. 数据字段名**就是后端列名**，`records` 可直接装载；非列字段（如徐的河南招生代号）收进 `meta.extra`，需要时再决定落列或单开表。
3. 装载实现沿用费 PR #12 的 8 个 importer 即可（`stg_import` 暂存层 + 幂等 upsert 的思路值得保留）。
4. `school_major_plan`（张的 1,696 条）**故意没并进** `school_major_score`：两套「院校专业组编号」不是同一体系（同校同年，徐为 502/504、张为 101/102），徐的 `major_code` 又大量为空，按组拼会写入错误值 —— 作独立数据集保留，等 `plan_count` 有明确的落地策略再合并。

## 七、怎么复现（验收命令）

```bash
# 1. 重建合并数据集（幂等，可反复跑）
python data/scripts/merge_datasets.py \
    --src-xu   <徐分支导出的 data/ 目录> \
    --src-zhang <张分支导出的 data/ 目录> \
    --out      <输出目录>

# 2. 合并结果校验：字段名是否落在目标表内 / 外键可解析率 / 来源三要素覆盖率
#    （脚本在 .workbuddy/scratch/pr/_validate_merge.py，按当前输出目录改 MERGED 常量）
#    末行输出「✅ 全部校验通过」即为通过，退出码 0

# 3. 层次标记专项核验
#    输出 39/112/147 名单的逐所核对 + 河南 985=0/211 全属郑大 + inherit 待确认清单为空
```

合并脚本自带断言，**数据或名单一旦不一致会直接报错中断**，不会静默产出错数据。
