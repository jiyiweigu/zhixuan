# 数据源与数据获取方案（智选志愿）

> 版本：v1.0 ｜ 2026-10-12 ｜ 责任人：队长（决策）+ 数据工程成员（执行）
> 适用变更：`add-admission-constraints`、`add-zhixuan-volunteer-assistant`
> **结论先行：不需要自建全量爬虫。现成 MIT 数据集已覆盖你要的 90% 数据；真正需要自建的只有两张几百行的小表。**

---

## 1. 先破除一个误区

「拿奖 = 把所有省份的一分一段表 + 所有学校所有专业的录取情况都爬下来」——这个前提是错的。

| 误解 | 实际 |
|---|---|
| 数据量决定分数 | 评分权重是 创新 25 / 技术 25 / 完成度 20 / 选题价值 10 / 应用传播 10 / 答辩 10，**没有一项考「收录了多少万条数据」** |
| 要自己爬 | 已有 MIT 许可的 1132 万行结构化数据集，四类表全齐 |
| 要全国 31 省 | 作品已定「**架构全面、数据分层**」：河南 + 江西做深做真，其余省标注「数据待接入」——**如实标注比假装全有更加分** |
| 体检限制要逐校逐专业查 | 教育部《体检工作指导意见》是按**专业类**给限制的，几百行映射表就够，不必逐校 |

真正的工作量在**数据治理**（版本、来源、状态、导入校验），而不是数据搬运。这部分你已经写进契约第 8 节了，是加分项。

---

## 2. 四道闸门 × 数据可得性（核心结论）

| 闸门 | 需要的数据 | 从哪来 | 自建工作量 |
|---|---|---|---|
| ① 省份规则 | 志愿模式 / 志愿数 / 是否服从调剂 / 投档比 | 各省考试院公告，人工录 | **小**：31 省 × 几年 = 几十行 → `province_exam_rule` |
| ② 选科要求 | 每个专业（组）的首选+再选科目要求 | ✅ **数据集直接有** `enrollment-plan.subject_req` | 中：需写**字符串解析器**转成 `{first, secondary[], logic}` |
| ③ 体检限制 | 专业类 × 身体条件 → 可不予录取 / 不宜就读 | ❌ 没有现成数据集；教育部《指导意见》原文 | **小**：按专业类建几百行 → `physical_restriction` |
| ④ 学费 | 每个专业每年的学费 + 办学性质 | ✅ **数据集直接有** `enrollment-plan.tuition` + `school-admission.school_nature` | 小：字段直取 |

**再加上推荐模块要用的**：
- 录取位次历史 → ✅ `school-admission.min_rank` / `major-admission.min_rank`
- 分数 ↔ 位次换算 → ✅ `score-range.csv`（一分一段表）

**一句话：四道闸门里只有「省份规则」和「体检」需要自建，且都是几百行的静态表；其余全部可由现成数据集直接导入。**

## 3. 数据源清单（按优先级）

### 3.1 一级：现成结构化数据集（首选，MIT 可商用可再分发）

**GaokaoCompass / Gaokao-Compass-11M**

| 项 | 值 |
|---|---|
| 地址 | HuggingFace `choucsan/Gaokao-Compass-11M`（镜像 `ghostwyx/Gaokao-Compass-11M`） |
| 仓库 | https://github.com/choucisan/GaokaoCompass |
| 许可 | **MIT**（可再分发） |
| 体积 | **1.42 GB**，1106 文件，861 个 CSV |
| 覆盖 | **31 省 × 2017–2025**，共 **11,327,563 行**；2022–2025 四表 31 省全覆盖 |
| DOI | doi:10.57967/hf/9882（可在作品说明里引用，学术可溯） |

目录结构（只下需要的省/年，不必全量）：

```
data/{year}/{province}/
├── enrollment-plan.csv     # 招生计划（含选科要求 + 学费 + 计划数）★ 闸门②④
├── school-admission.csv    # 院校投档线（最低分 + 最低位次 + 办学性质）★ 闸门④ + 推荐
├── major-admission.csv     # 专业级录取（最低/最高/平均分 + 位次）★ 推荐
├── score-range.csv         # 一分一段表 ★ 位次换算
└── meta.json               # 该省该年概览（考生数、批次线、985/211 数）
```

关键字段对照（**直接决定数据成员怎么写导入脚本**）：

| 数据集字段 | 我们的逻辑表 | 备注 |
|---|---|---|
| `enrollment-plan.subject_req` | `subject_requirement.first / secondary[] / logic` | 字符串需解析，见 §4.1 |
| `enrollment-plan.tuition` | `major_tuition.amount`（元/年） | 直取 |
| `enrollment-plan.plan_count` / `duration` | 招生计划展示（产品要展示） | 直取 |
| `school-admission.school_nature` | `major_tuition.ownership` | 公办/民办 → 影响学费闸门 |
| `school-admission.min_rank` / `min_score` | 推荐算法输入 | 直取，含 `is_985/is_211` |
| `major-admission.*` | 专业级历史 | 直取 |
| `score-range.score / cumulative_count` | 一分一段（分数→位次） | 直取，单省单年仅 **~45 KB** |
| — | `physical_restriction` | ❌ 无，需自建（§4.2） |
| — | `province_exam_rule` | ❌ 无，需自建（§4.3） |

**体量感知**：单省单年约 8–9 MB（大头是招生计划和专业录取）。**只取河南 + 江西 × 近 3 年 ≈ 50 MB**，完全可控。

### 3.2 二级：免鉴权实时接口（补最新年份）

- **`static-data.gaokao.cn`** —— 中国教育在线 / 掌上高考的**静态 JSON 层**，实测 `https://static-data.gaokao.cn/www/2.0/school/school_code.json?a=www.gaokao.cn` 返回 `{"code":"0000"}` + 院校字典，**免鉴权、免签名、观测不到频率限制**。
- `api.eol.cn/web/api/?uri=apidata/api/gkv3/...` —— 分页接口（每页 10 条），**有反爬**（UA 检测 + 频率限制），非必要不用。
- 用途：数据集只到 2025 年，**2026 年数据从考试院或此接口补**。
- 参考实现：`HA7CH/gaokao-pro`（MIT）已把 `static-data.gaokao.cn` 的调用契约整理好，并附 `docs/data-sources.md`（31 省考试院 URL 清单）。

### 3.3 三级：一手官方源（署名用，权威性背书）

| 来源 | 用途 | 地址 |
|---|---|---|
| 河南省教育考试院 | 一分一段表、志愿模式、批次线 | `haeea.cn` |
| 江西省教育考试院 | 同上 | `jxeea.cn` |
| 阳光高考（教育部） | 招生章程、专业库、各省一分一段表转发 | `gaokao.chsi.com.cn` |
| 教育部《普通高等学校招生体检工作指导意见》 | 体检限制的**唯一权威依据** | 教育部官网 |

**作品里每一条事实性结论的 `source_name / source_url / year` 应该是这一层**，而不是"掌上高考"。数据集只作为**获取渠道**，署名要给到上游官方。这一点正好契合你契约里「来源三要素」的强制要求。

### 3.4 四级：仅供比对（不采信、不入库）

优志愿、蝶变志愿、圆梦志愿、百度/夸克高考等商业平台 —— 只用来交叉验证我们导出的数据对不对，**不作为数据来源，也不要在作品里引用**。

## 4. 三个需要动手的活

### 4.1 选科要求字符串解析（交给数据工程）

`enrollment-plan.subject_req` 是自由文本，形如 `物理+化学`、`化学或生物`、`不限`、`物理*化学`。需要写解析器转成契约 §8.6 的结构：

```python
# 目标：{"first": "物理", "secondary": ["化学"], "logic": "all"}
# "物理+化学"      -> first=物理, secondary=[化学], logic=all
# "化学或生物"      -> first=null, secondary=[化学,生物], logic=any
# "不限"           -> first=null, secondary=[],    logic=all   ← 必须与"数据缺失"可区分
```

**关键**：`不限` 和「没数据」必须能区分（契约已强制要求）。解析失败的行**不能猜测**，一律进 `missing_rule_sets`，靠 `rule_dataset_status` 表达。

### 4.2 体检限制表（交给队长或算法成员）

依据教育部《体检工作指导意见》，构建 `physical_restriction`：
- 粒度：**专业类**（不是逐校逐专业）
- 两类级别：`reject`（不予录取）/ `not_suitable`（不宜就读，可报但建议不报）
- 覆盖：色觉异常（色弱/色盲/不能识别红黄绿蓝紫）、视力、身高、乙肝、听力、嗅觉、口吃

这是产品**最有价值的差异化点**，因为「体检不满足 = 报得上但会被退档」是绝大多数志愿工具忽略的坑。**这张表值得手工精做**。

### 4.3 省份志愿模式表（交给数据工程）

`province_exam_rule`：面向河南、江西本科批先做真，字段照契约 §8.7。已知口径：

| 省份 | 模式 | 志愿数 | 每组专业数 | 是否调剂 | 首年新高考 |
|---|---|---|---|---|---|
| 河南 | 院校专业组 | 48（本科批） | 6 | 是 | 2025 |
| 江西 | 院校专业组 | 45（本科批） | 6 | 是 | 2024 |

⚠️ **口径断裂必须处理**：河南 2025、江西 2024 才首次新高考，之前是「理科/文科」。数据集里 2017–2023 的科类与现在的「物理类/历史类」不是一回事，**跨年对比必须按位次、不能按分数**（你的设计文档已强调这点，导入时要在脚本里强制标记 `exam_system`）。

## 5. 落地路径（三层，与现有架构对齐）

```
第一层 · 全量底座（一次导入，不用核实）
  GaokaoCompass 31 省 × 2017–2025 → 导入脚本 → PostgreSQL
  字段带 source_name='中国教育在线(渠道)/省考试院(上游)' + year
  状态一律先标 schema_only / partial，不标 available

第二层 · 试点核实（河南 + 江西，逐条对官方源）
  用省考试院公告核对本科批模板、批次线、一分一段表
  核对通过 → 该数据集 status 才能升 available
  ← 这一步是「得奖」的关键：体现数据治理能力，而不是数据量

第三层 · 分层呈现（产品层如实标注）
  P0 河南/江西本科批：完整四闸门校验
  P1 其他省：可查历史录取/位次，报考约束显示「规则待接入」
  P2 其他批次：仅架构支持，UI 明确「暂不支持」
```

**注意 `.gitignore` 已忽略 `data/raw/*` 和 `data/**/*.csv`** —— 这是对的，**1.42 GB 数据不要入库**。仓库里只放：导入脚本（`data/scripts/`）、数据字典、校验脚本、下载指引 + 每个文件的 SHA256 清单。

## 6. 合规红线（必须做）

1. **署名到上游**：事实结论的 `source_url` 指向省考试院 / 阳光高考，不指向第三方平台。
2. 掌上高考页面声明「本站数据未经授权严禁转载」→ 作品内**不做数据再分发**，仅作为开发期获取渠道；导出物不在仓库公开（`.gitignore` 已挡）。
3. 数据集是 **MIT**，可再分发，但仍应保留其 DOI 引用（doi:10.57967/hf/9882）。
4. 作品说明文档里**明确写一节「数据来源与合规声明」**：来源、年份、许可、局限（如"仅供参考，最终以省级考试机构结果为准"）。评委很吃这一套。
5. 体检信息属敏感个人数据：档案按最小必要采集，**不采集身份证号、不上传体检报告原件**（契约已写）。

## 7. 下载方式（含国内镜像）

```bash
# 国内网络建议走 HF 镜像
export HF_ENDPOINT=https://hf-mirror.com        # Windows: set HF_ENDPOINT=...

# 方式一：只下需要的省份/年份（推荐，省流量）
# 直接取单文件，如河南 2024 一分一段表
curl -L -o data/raw/2024_henan_score-range.csv \
  "$HF_ENDPOINT/datasets/choucsan/Gaokao-Compass-11M/resolve/main/data/2024/henan/score-range.csv"

# 方式二：整仓（1.42 GB）
huggingface-cli download choucsan/Gaokao-Compass-11M --repo-type dataset --local-dir data/raw
```
