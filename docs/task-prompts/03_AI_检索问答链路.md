## 任务要求：`services/qa.py` 的真实问答链路

按顺序实现并替换演示实现：

1. **混合检索**：向量检索 top-N + BM25 top-N → `ai_support.rrf_merge` 融合 → 取融合后 top-K。
2. **重排**：bge-reranker 对 top-K 重排（同样走适配器模式：Fake 版确定性打分，测试不依赖网络/模型下载；真模型从环境变量配置端点或本地加载）。
3. **生成**：qwen-plus（OpenAI 兼容 API，密钥环境变量）。提示词要求：**仅基于检索到的知识片段作答**，逐条标注引用；片段不足以回答时明确说知识库暂无数据。系统提示里注入用户省份（河南试点）等上下文。
4. **置信度**：`ai_support.classify_confidence` 分档（高/中/低），输出进响应体 confidence 字段。
5. **低置信入审核**：confidence 为低档时，按表结构写入 `review_task`（管理端 M6 的审核闭环由此获得真实数据流）。
6. **日志**：每次问答写 `qa_log`（问题、命中片段、置信度、耗时、兜底与否）。
7. **兜底优先**：检索无证据 → 直接 `restricted_answer`，**不调用生成模型**（这条写死，不允许「检索为空还硬生成」）。
8. **演示/真实可切换**：沿用项目惯例——无有效模型配置时自动回落演示实现并明确标记（参照 `core/demo.py` 与 T2 的 FakeEmbedder 做法），保证评委在无密钥环境下演示不炸。
