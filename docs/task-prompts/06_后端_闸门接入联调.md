## 任务要求

1. **闸门②接入**：引擎从规则数据（库内或随仓库字典——**优先走库内，与 importers/rule_admin 通道一致**）读选科要求，对考生选科做判定：
   - first 不满足 → `blocker`（报不了）；
   - secondary 按 `logic`（all/any）判定 → 不满足 `blocker`；
   - 目标（某院校专业组）**查无规则行** → `unknowns` + 返回 `3001` 标记（不静默放行）；解析状态为 `unparsed` 的行同样进 `unknowns`；
   - 老高考年份/省份无选科概念（`missing`）→ 如实进 `unknowns` 或按省份规则闸门给出「该省当年非选科模式」的 warning——**与既有闸门①省份规则的行为对齐，不发明新语义**。
2. **闸门③接入**：考生体检字段（档案 11 字段）× 目标专业类 → 映射表判定：
   - `severity=blocker` 命中 → `blockers`（附依据 `basis` 文本——溯源展示）；
   - `severity=warning` 命中 → `warnings`（附依据）；
   - 考生体检字段为 `null` → **`unknowns`，绝不判合格**；
   - 专业类查无映射 → `unknowns`（宁可缺不可猜）。
3. **保持纯函数**：规则数据以参数/只读快照传入引擎；DB 读取在服务层完成（`engine/` 内不得 import sqlalchemy/requests）——这是架构红线。
4. **江西规则补全**：`province_exam_rule` 目前只有 7 条、江西志愿模式仅 3 条规则——依据江西省 2025 年普通高校招生实施办法（官方公开文件，jxeea.cn）补全江西的批次/志愿模式/选科模式规则行，经 importer 通道入库，来源登记进 source-table。
5. **测试扩展**（在 `test_constraints.py` / `test_engine.py` 增用例，不删既有用例）：
   - 闸门②：满足/不满足 first、secondary all 与 any、无规则 → 3001+unknowns、unparsed → unknowns；
   - 闸门③：blocker 命中、warning 命中、体检 null → unknowns、专业类无映射 → unknowns、依据文本随结果返回；
   - 串行四闸门端到端：一个考生档案过四闸门的综合用例（含跨闸门 blockers 聚合）。
6. **对账**：PR 里报告 unparsed/missing 规则占比（来自 T4 产出的真实数据），以及预计触发 3001 的专业组比例——这决定演示话术。
