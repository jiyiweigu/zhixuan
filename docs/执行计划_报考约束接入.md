## 1. 范围：做什么、不做什么

**做**：档案前置采集（两段式）→ 四道闸门纯函数引擎 → 路径级 + 志愿单位级两级校验 → 三档结果（🔴硬拦 / 🟡软提示 / ⚪待核验）→ 「志愿表风险体检」页。

**不做**（明确排除，避免范围膨胀）：

- ❌ 不新增独立菜单/独立模块，全部挂在 `/profile`、`/eligibility`、`/plan` 三条既有路由下
- ❌ 不用大模型做任何约束判定（沿用 D6：必须可复核、可溯源）
- ❌ 不做**静默过滤**（用户在搜索时仍能看到被拦项 + 原因）
- ❌ 不在本次范围内做全 26 类途径的约束数据，只做 **P0 两省本科批**

## 3. 不返工的顺序（关键）

你前端已经在写了，所以顺序要按"**契约 → 数据入口 → 结论展示 → 编辑器校验**"来，而不是按模块分：

```
P0 契约三件套 ──┬─► P1 档案两段式（数据入口，必须先做）
  （队长）      │      └─► P3 资格自检页（专业适配）──┐
                │                                    ├─► P4 志愿表风险体检（编辑器侧）
                └─► P2 四道闸门引擎 + 规则数据（②③ 并行）┘
```

| 阶段 | 内容 | 负责人 | 依赖 | 建议日 |
|---|---|---|---|---|
| **P0** | 契约三件套（第 2 节） | ① | — | D1 |
| **P1** | 档案两段式 + 完成度（数据入口） | ① | P0 | D2–D3 |
| **P2** | 四道闸门引擎（选科 / 身体 / 学费 / 省份模板）+ 规则数据入库 | ②③ | P0（只依赖契约，不依赖前端） | D2–D5 |
| **P3** | 资格自检页扩展"专业适配" + 三档标签 | ① | P1、P2（Mock 可先行） | D4–D6 |
| **P4** | 「志愿表风险体检」（方案页）+ 被过滤项抽屉 | ① | P3 | D6–D8 |
| **P5** | 管理端规则维护（按年份版本） | ⑤ | P2 | D7–D9 |
| **P6** | 边界用例 ≥30 条 + 验收 | ②③④⑤ | P2 | D9–D10 |

> **P2 与前端的唯一耦合是 JSON 契约**。所以 ②③ 从 P0 完成当天就可以动手，不必等页面。

## 6. 验收口径（可执行）

| 检查 | 通过标准 |
|---|---|
| 类型检查 | `npm run typecheck` 退出码 0 |
| 契约一致性 | 6.2.6–6.2.9 四接口在前端 `api/index.ts`、`types`、`mocks` 三处字段完全一致 |
| 引擎幂等 | 同输入连调两次，输出 JSON 完全相同 |
| 三档覆盖 | Mock 与真实实现均能产出 `blockers` / `warnings` / `unknowns` 各 ≥1 |
| 边界用例 | ≥30 条全绿，含"色弱→医学类"，**且"未填体检"不得判为通过** |
| 溯源 | 每条 `blockers`/`warnings` 都带 `citation`（三要素齐全） |
| 无静默过滤 | 被拦项在主动搜索时仍可见 + 有原因说明 |
| 规则缺失 | 删掉规则数据后请求返回 `3001`，前端显示"规则数据缺失"而非"通过" |

## 7. 数据没到位时的降级（很重要）

P0 数据（两省本科批）可能晚于引擎完成。**不允许因此停摆**，按此降级：

| 缺什么 | 降级做法 |
|---|---|
| 完整招生计划 | 先用 `mocks` 的三档样例跑通全链路 UI，`data_status=schema_only` 如实标注 |
| 完整选科要求 | 先只上「物理+化学」绑定规则（覆盖面最大，约占理工农医 90%） |
| 完整体检清单 | 先上色觉 + 裸眼视力两类（退档最高频），其余标"规则数据待补" |
| 学费精确值 | 按办学性质分档估算，**必须标注"估算"**并降 `reliability` |

> **红线**：任何"数据缺失"都必须显式暴露给用户（`unknowns` 或 `3001`），**绝不能用默认放行来假装完整**。
