# 报考规则与限制条件设计（志愿模式 · 选科 · 体检 · 学费）

> **定位**：本文是《开发产品书_智选志愿》功能拆解的**规则层补充设计**，对应 M3（路径/资格自检）与 M5（志愿方案生成）中的"硬约束"部分。
>
> **版本**：v0.1（2026-10-12）
> **依据**：教育部《普通高校本科招生专业选考科目要求指引（通用版）》、《普通高等学校招生体检工作指导意见》；河南省 2025 年普通高校招生考试和录取工作实施方案；江西省 2025/2026 年志愿填报及投档规则。
>
> **总原则**：一切规则以**当年、该省、官方**公布的招生计划与招生章程为准。本设计只负责把规则建模成"可复算、可溯源的校验"，不替代官方数据。

---

## 1. 你提的三件事，本质是同一层问题

统一命名为 **报考资格与适配约束（Eligibility & Fit Constraints）**，共四类：

| 约束 | 决定什么 | 违反的后果 |
|---|---|---|
| 省际规则（志愿模式） | 志愿**怎么填**、能填几个 | 结构错误、填不进系统 |
| 选科匹配 | 这个专业组**能不能报** | 系统直接不让填（硬拦截） |
| 身体条件（体检） | 这个专业**录不录** | 投档后被**退档**（最惨） |
| 经济（学费/办学性质） | 这个专业**读不读得起** | 录取后放弃、家庭负担 |

**关键洞察**：选科不满足是"报不了"，**体检不满足是"报得上但会被退"**。后者更危险——已经投档了才发现不合格，直接落榜，只能等征集志愿。这正是本产品最能体现价值的地方。

## 2. 省际志愿模式：必须按「省份 × 批次」分模板

### 2.1 三种志愿单位模式

| 模式 | 1 个志愿 = | 是否服从调剂 | 适用 |
|---|---|---|---|
| **院校专业组** | 1 个院校专业组（内含 1–6 个专业） | 有，**仅组内**调剂 | 新高考主流（河南、江西） |
| **专业 + 院校** | 1 个专业 + 1 所院校 | 无 | 河南提前批/艺术/体育等 |
| **院校 + 专业**（老高考） | 1 所院校 + 若干专业 | 有，校内调剂 | 少数未改革省份 |

### 2.2 试点两省现行设置（须逐年核对）

**河南（2025 起「3+1+2」）**

- 普通本科批：**48 个院校专业组**，每组 **6 个专业志愿 + 是否同意专业调剂**
- 普通本科提前批：**64 个「专业+院校」**（不设调剂）；专科层次公安/司法 12 个
- 艺术本科批 / 体育本科批 / 高职（专科）提前批：64 个「专业+院校」
- 艺术本科提前批：1 个院校志愿 + 4 个专业 + 调剂
- 提前批各类**不得兼报**（军事/公安/司法/师范/行业/其他 六选一）
- 艺术类与体育类**不能兼报**

**江西（2024 起「3+1+2」）**

- 本科批：**45 个院校专业组**，每组 6 个专业 + 是否服从专业调剂
- 提前本科军警类：45 个院校专业组平行志愿；征集志愿 20 个
- **2026 变化**：① 原则上按专业招生、严控大类招生；② 专业组内各专业选科要求必须一致（调剂更"纯"）；③ 高校专项改为省级统一审核、纳入本科批平行志愿
- **2026 起不再公开**各专业组投档线，仅在省平台对本人定向发布 → **影响数据获取策略**

### 2.3 建模：`province_exam_rule` 表

字段（省 × 年 × 批次）：

| 字段 | 含义 |
|---|---|
| `mode` | `group`（院校专业组）/ `major_school`（专业+院校）/ `school_major`（老高考） |
| `volunteer_count` | 志愿单位数（河南本科批 48 / 江西本科批 45 / 提前批 64…） |
| `majors_per_group` | 每组专业上限（6） |
| `has_adjust` | 是否有"服从调剂"选项 |
| `admit_method` | `parallel`（平行）/ `single`（单志愿） |
| `ratio` | 投档比例（一般 1:1） |
| `tie_rule` | 同分排序规则 |
| `mutex_groups` | 兼报限制（提前批各类互斥） |
| `collect_count` | 征集志愿名额 |

> **方案生成器必须按此模板渲染志愿表**：河南本科批输出"48 行 ×（1 组 + 6 专业 + 调剂）"；江西输出"45 行…"；河南提前批输出"64 行 专业+院校，无调剂"。模板不同，导出格式就不同。

## 3. 选科匹配引擎

### 3.1 教育部的四类要求

1. **不提科目要求** → 任意组合可报
2. **只限首选**：如"物理" → 首选物理即可
3. **只限再选**：如"化学" / "化学,生物"（须均选）
4. **首选 + 再选**：如"物理,化学" / "物理,化学,生物"

### 3.2 关键事实

- 《通用版》指引自 **2024 年招生起适用**；理学/工学/农学/医学 **61 个专业类中 55 个要求「物理+化学」**（约 90%，即"物化绑定"）
- 公安学类、政治学类、马克思主义理论类通常**必选政治**
- **同一专业在不同高校要求可能不同**；最终以**当年该省招生计划**为准

### 3.3 匹配算法（纯函数，沿用 D6：不用大模型）

```python
def subject_match(profile, req) -> bool:
    # profile: first='物理'|'历史', secondary={'化学','生物',...}
    # req:     first=None|'物理'|'历史', secondary={'化学',...}, logic='all'|'any'
    if req.first and req.first != profile.first:
        return False
    if req.secondary:
        ok = (all(s in profile.secondary for s in req.secondary)
              if req.logic == 'all'
              else any(s in profile.secondary for s in req.secondary))
        if not ok:
            return False
    return True
```

输出：`eligible / ineligible` + 缺失科目说明 + 依据来源（省份/年份/计划）。

## 4. 体检校验引擎（产品最有价值的差异点）

### 4.1 体检结论三态

| 结论 | 含义 | 处理 |
|---|---|---|
| **合格** | 正常报考 | 通过 |
| **合格不宜** | 能读，但就业/发展可能受限 | **软提示**（高校不得因此拒录，但建议慎重） |
| **不合格** | 不予录取 | **硬拦截** |

### 4.2 硬性不予录取清单（结构化）

| 体检条件 | 不予录取的专业（节选） |
|---|---|
| **轻度色觉异常（色弱）** | 化学类、化工与制药类、药学类、生物科学类、公安技术类、地质学类各专业，**医学类各专业**；生物工程、生物医学工程、动物医学、心理学、生态学、食品科学与工程、农学、园艺、园林、**体育教育**等 |
| **色觉异常Ⅱ度（色盲）** | 除色弱项外，另含美术学、绘画、艺术设计、摄影、动画、应用物理学、天文学、地理科学、材料物理、冶金工程、交通运输、油气储运工程等 |
| **不能识别红/黄/绿/蓝/紫任一色** | 除上述外，另含经济学类、管理科学与工程类、工商管理类、公共管理类、图书档案学类等；**不能在显示器上识别颜色者不能报计算机科学与技术等** |
| **裸眼视力 < 5.0** | 飞行技术、航海技术、消防工程、刑事科学技术、侦察 |
| **裸眼视力 < 4.8** | 轮机工程、运动训练、民族传统体育 |
| **乙肝表面抗原携带** | 学前教育、航海技术、飞行技术等 |

### 4.3 必须拦住的真实退档场景

江西官方问答原话：本科批征集志愿中"医学类专业缺额"，常因**色弱考生填报医学类被退档**造成。

→ 我们的产品要在**填之前**就提示："你是色弱，医学类会被退档。"

### 4.4 建模：`physical_restriction` 表

- `condition`（色弱 / 色盲 / 色识别 / 裸眼视力 / 乙肝 / 身高 / 体重 / 听力 / 嗅觉 / 口吃 …）× 阈值
- 影响 `major_category` / `major_code` 清单
- 严重级别：`reject`（不予录取，硬） / `not_suitable`（不宜就读，软）
- 档案侧结构化采集：`color_vision`、`vision_left/right`、`height`、`weight`、`hepatitis_b`、`hearing`

## 5. 学费与办学性质

| 类型 | 大致区间 |
|---|---|
| 公办普通专业 | 5–6 千 / 年 |
| 民办本科 | 1.5–3 万 / 年 |
| 中外合作办学 | 2–6 万 / 年，个别更高 |
| 艺术类 | 普遍高于同校普通专业 |

- 档案增加 `fee_ceiling`（可承受上限）
- 方案中对超预算项标黄 + 提示奖助贷（助学贷款、助学金；公费师范、定向医学生可减免）

```
考生档案 ──► [1 省份规则] ──► [2 选科匹配] ──► [3 体检校验] ──► [4 学费预算] ──► 每个志愿单位：
```

## 8. 你可能还没考虑到的（按优先级）

### ★ 必补——直接影响"会不会退档"

1. **退档原因不止体检**：① 不服从专业调剂；② 单科成绩不达标（如某专业要求外语 ≥ 120）；③ 外语语种不符（非英语考生受限）；④ 性别限制；⑤ 面试/政审/体测未通过（军警、公费师范、定向招生）；⑥ 身体条件。建议做一张**统一的"退档风险清单"**，这是产品的核心卖点。
2. **"服从调剂"的真实含义**：院校专业组下，服从调剂**只在本专业组内**调剂；不服从且专业分不够 → 直接退档。要教用户"什么时候必须勾服从"。
3. **征集志愿**：每批次录取后有名额、可降分投档，是**被退档后唯一的补救**。产品应做"退档 → 征集志愿"提醒。
4. **兼报与批次顺序**：提前批各类不得兼报、艺体不能兼报、提前批在本科批之前投档——填错顺序等于白填。

### ● 建议补——影响体验与完成度

5. **用位次而非分数**：跨年比较必须用**位次 / 一分一段表**，直接比分数误差极大。注意 2026 江西不再公开投档线，数据策略要提前想。
6. **填报时间线**：河南 3 次填报、江西 2 次，各批次时间不同，且系统**限时 50 分钟** → 做"填报日历 + 倒计时"。
7. **加分政策**：烈士子女 +20、自主就业退役士兵 +10、归侨/华侨子女等 +5，**不累加、封顶 20**，须公示。
8. **"藏在招生章程里"的要求**：单科成绩、外语语种、身体条件、性别、面试——不在计划表里，只在各校招生章程 → 正好用 RAG 从章程中抽取。
9. **办学地点 / 校区**：同校不同专业可能在不同城市或校区，直接影响生活成本（与"院校生活信息"模块打通）。
10. **大类招生分流风险**：2026 严控但仍有，大二分流可能进冷门专业。
11. **特殊考生类型**：艺术（统考/校考）、体育、三校生、对口招生、专升本、港澳台侨、保送生——各自独立规则。
12. **特殊类型招生**：强基计划、综合评价、国家/地方/高校专项、高水平运动队/艺术团，都有**独立报名时间线**（往往在高考前），别只在填报期才想起。

### ○ 合规与安全

13. **不承诺录取结果**：全站声明"仅供参考"，所有输出带依据。
14. **隐私**：分数、位次、体检结论、身份证均属敏感信息；仓库已开源 → **绝不放真实考生数据**。
15. **数据时效与可信度**：计划/学费/选科每年变，必须标注年份与来源等级（官方 / 非官方）。

### 一个"隐藏加分项"

16. **志愿履约记录**：河南规定"录取后不入学造成招生计划浪费"者，次年填报志愿数量受限（如不超过 24 个）。可提醒用户"录取后慎重放弃"。

## 9. 收敛方案：档案前置采集 + 资格引擎统一校验

> 2026-10-12 与队长确认：四类约束不单独做模块，**统一收敛进"资格自检"**，由档案驱动。

### 9.1 三个概念要分清

| 概念 | 角色 |
|---|---|
| **考生档案 `candidate_profile`** | **唯一事实来源**：选科、体检、预算、户籍/学籍、意向批次… 全部前置采集 |
| **资格引擎 `eligibility engine`** | **唯一的约束校验入口**：四道闸门（省份规则 / 选科 / 体检 / 学费） |
| **资格自检** | 该引擎的**一个视图**，从"只管升学路径资格"扩展为**同时覆盖「路径」与「专业」两个层面** |

> 命名建议：原 `pathway-eligibility` 扩展 / 更名为 `admission-eligibility`，因为它现在管的不只是路径。

### 9.2 三个触发时机

1. **档案录入时**——增量校验，逐项即时反馈（填完选科 → 立刻提示"你的可报专业范围"变化）
2. **浏览 / 推荐时**——前置过滤 + 标注（**不是静默隐藏**）
3. **生成方案 / 提交前**——全表扫描（"志愿表风险体检"）

### 9.3 三档处理策略（关键，禁止一刀切）

| 档 | 情形 | 处理 |
|---|---|---|
| 🔴 **硬拦截** | 选科不符、体检"不合格"、无对应专项资格 | 默认不进推荐候选；用户主动搜索时仍**显示**并注明"不可报 + 原因" |
| 🟡 **软提示** | 体检"合格不宜"、学费超预算、单科/语种风险、退档风险 | **保留在结果中**，显著标注 + 说明 + 依据 |
| ⚪ **未知** | 档案信息缺失（如未填体检） | **既不默认放行、也不默认拦截**，标"待核验"并引导补全 |

### 9.4 为什么不能纯静默过滤

1. **信任**：什么都看不到，用户会怀疑"平台数据不全"，也不知道为什么少了一大批院校。
2. **竞赛演示**：答辩时能直观展示——"你色弱，这 37 个医学类专业被拦下，依据是《体检指导意见》第 2 条第 1 款"，这是加分点。
3. **纠错**：体检结论可能填错，全隐藏用户就发现不了自己的输入错误。
4. **可达性**：必须提供"**查看被过滤项**"开关。

### 9.5 落地约束

- 档案分两段：**必填**（省份/年份/选科/分数·位次）→ **选填但强影响**（体检/预算/户籍学籍）。给"完成度"进度条，未填部分**明确标注它影响的推荐范围**。
- 体检信息属敏感项，且很多学生不记得自己的体检结论 → 允许"暂不填"，但**必须标注"未校验风险"**，不能默认放行。

### 9.6 契约影响

- `candidate_profile` 增加字段：`first_subject`、`secondary_subjects[]`、`color_vision`、`vision_left/right`、`height`、`weight`、`hepatitis_b`、`fee_ceiling`、`batch_preference[]`。
- 新增统一入口 `POST /api/eligibility/check`：**支持批量**（传一批志愿单位做校验），返回统一结构：

```json
{
  "unit_id": "...",
  "eligible": false,
  "blockers": [{"type": "physical", "level": "reject", "detail": "色弱不能录取医学类", "citation": {...}}],
  "warnings": [{"type": "fee", "level": "soft", "detail": "学费 5.8 万/年，超出你的预算上限"}],
  "unknowns": [{"type": "physical", "detail": "未填写体检结论，无法校验"}],
  "citations": [...]
}
```
