# 数据库装载操作手册

## 前置条件

- 已合并的外部数据目录 `智选志愿_数据整合\merged`（合并产物背景见 `docs/数据整合与装载交接.md`）；
- Python 项目依赖（backend venv）；数据本体与数据库都放在仓库外；
- 合并产物更新后先重跑 staging——`stage_load_root.py` 内置三道入口校验
  （records 列表 / `meta.target_table`+`meta.count` / school 行 `source_id` 逐行必带），
  数据不合格会被直接拒绝，不带病装载。

## 快速执行（三步）

```powershell
python data/scripts/stage_load_root.py
Push-Location backend
python -m alembic upgrade head
$env:ZHIXUAN_DATA_ROOT="C:\Users\Administrator\Desktop\智选志愿_数据整合\load_root"; python -m app.services.importers
Pop-Location
```

`ZHIXUAN_DATA_ROOT` 指向 staging 根目录；`ZHIXUAN_DATABASE_URL` 可覆盖数据库连接。
空库验证请使用新的临时 SQLite 路径，避免触碰已有数据。

装载是**幂等**的：同一份数据重复执行「新增 / 更新」均为 0。切换数据源
（合并数据集 ↔ 仓库内原始专业库）前请**清库重装**——两态的 id 分配顺序不同，混装
会令下游 `major_id` 引用错位（混装会被检测并在报告里计数上报，不会静默覆盖）。

重点 SQL：

```sql
-- 层次标记（整合期修复：0→52 / 3→135 / 8→171）
SELECT name,is_985,is_211,dual_class FROM school
WHERE name IN ('清华大学','北京大学','郑州大学');

-- 悬空外键必须为 0；NULL 是如实留空（'宁可缺、不可猜'）
SELECT COUNT(*) FROM school_major_score
WHERE school_id IS NOT NULL AND school_id NOT IN (SELECT id FROM school);
SELECT COUNT(*) FROM school_major_score
WHERE major_id IS NOT NULL AND major_id NOT IN (SELECT id FROM major);
SELECT COUNT(*) FROM school_major_score WHERE school_id IS NULL;
SELECT COUNT(*) FROM school_major_score WHERE major_id IS NULL;

-- 抽查真实挂接（专业名经 major 表 join 得到）
SELECT s.name, m.name, sms.min_score FROM school_major_score sms
JOIN school s ON s.id = sms.school_id JOIN major m ON m.id = sms.major_id
WHERE s.name = '郑州大学' AND sms.year = 2025 LIMIT 10;
```

## 已知差异（如实登记，非缺陷）

- `school_id`：院校库外引用 40 行（含 1 行 35 位乱码 id，会触发 OverflowError 的那种）
  已按红线置 NULL，全表 NULL 共 2,022 行；**非 NULL 悬空 0**。
- `major_id`：NULL 2,200 行——试验班 509 / 理科试验班 143 / 职业本科专业等客观缺失。
- `admit_count`：约 7.8 万行携带「实际录取数」，与计划数 `plan_count` 语义不同，
  **不落库**（如实登记）。
- pathway `general-batch` 引用缺失 1 行、艺术/体育一行两类 1 行：跳过并上报。

以上差异均可在装载报告的 `skip_reasons` 与 note 中复核；实际落库数量以
`check_load_counts.py` 输出为准。
